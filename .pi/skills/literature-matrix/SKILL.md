# 批量精读 → 证据矩阵

围绕一个明确的研究问题，把用户提供的论文整理成逐篇可追溯的证据矩阵。检索命中、Zotero 元数据、摘要和文件名都只是定位线索；只有 `research_read_source` 成功读取的原文内容才能进入“主要结论”或“与研究问题的关系”。

## 输入与批次边界

开始前确认两个输入：

1. **论文集合**：Zotero 集合、DOI 列表，或项目目录中的 PDF 文件夹。可以组合提供。Zotero 和 DOI 先通过宿主的文献连接器解析为来源；项目文件夹只使用当前工作区内的文件。
2. **研究问题**：保留用户原句，不把它改写成论文标题，也不要把一篇论文的主题当成研究问题。

规范化并去重后，单批最多处理 12 篇。按 DOI 去重，再按 arXiv id，最后按规范化标题和同一文件路径去重。超过 12 篇时先处理前 12 篇，明确告诉用户剩余数量和下一批的输入范围；不要在同一批静默扩大并行数量。没有可解析的原文来源时仍然交付矩阵行，但要如实写明没有读到原文。

## 每篇论文的子代理任务

父会话为每篇论文派一个有界子代理，子代理只负责当前论文的读取和结构化回传，不写主 Vault、不修改 Zotero、不下载来源。把来源身份（DOI、Zotero key 或项目内相对路径）和研究问题一并传给它。

子代理必须按这个顺序执行：

1. 对已解析的来源调用 `research_read_source`，必要时设定合理的 `max_chars`，并保留工具返回的 `source_id`、URI、hash、行范围和页码回执。PDF 文本中的 `[[page:N]]` 是唯一可以生成 `#page=N` 的依据。
2. 只根据这次读取到的原文填写固定字段：**研究问题、方法、数据/样本、主要结论（带页码）、局限、与研究问题的关系**。每条结论都在同一字段中紧邻 `source_id` 和 `#page=N`；没有读到页码就不要猜页码。
3. 如来源不可读、只有摘要/元数据、PDF 损坏、连接器失败或读取回执不完整，所有依赖原文的字段写 **“未读到原文”**，并保留失败原因和可复核的来源身份。不得用摘要补全方法、样本、结论、局限或关系判断。
4. 返回一条结构化记录，不返回长篇论文复述。记录至少包含 `status: read | unread`、`title`、`doi_or_locator`、六个固定字段、`source_id`（可读时）和 `pages`（可读时）。

子代理的输出不是知识库写入回执。父会话必须重新检查每条记录是否有本轮 `research_read_source` 回执，才能把它纳入矩阵；子代理声称“已读”不能替代工具回执。

## 父会话汇总与沉淀

父会话收齐本批记录后：

1. 在项目目录写入 `literature-matrix.md` 和 `literature-matrix.csv`（如已存在则在用户授权范围内更新本批，不覆盖其他项目文件）。Markdown 表格列为：论文、DOI/定位、研究问题、方法、数据/样本、主要结论（页码）、局限、与研究问题的关系、原文状态。CSV 使用 UTF-8，第一行为固定字段名；对单元格中的逗号、引号和换行做标准 CSV 转义，确保可被表格软件打开。
2. 矩阵行必须保留 `read` / `unread` 状态。`unread` 行的六个字段不得写摘要推断；可以写“未读到原文（原因）”。在文档开头注明研究问题、来源范围、批次编号和未处理的剩余数量。
3. 父会话调用 `research_deposit_knowledge`，使用 `type: "evidence"`，标题包含研究问题和批次，Markdown 使用矩阵正文，`source_links` 只放实际读取来源的 URI/DOI/项目路径；有未读行时将 `status` 设为 `unverified`，即使整批都未读到原文也要沉淀矩阵的缺口记录。不可读论文保留在矩阵中，但不得作为已验证来源链接或引用。
4. 沉淀返回的 Vault 路径和写入状态要记录在矩阵末尾；工具失败时保留本地 Markdown/CSV，报告失败原因，不声称已写入知识库。不要调用原始 Obsidian 写接口或用 `research_deposit_research_note` 冒充 `research_deposit_knowledge`。

## 证据纪律

- 搜索结果、摘要、引用计数、Zotero 注释和子代理转述都不能单独支持结论。
- 页码只能来自当前 `research_read_source` 回执中实际读到的 `[[page:N]]` 范围；使用 `<来源>#page=N` 时，N 必须在回执范围内。
- 研究问题的关系字段要区分直接支持、间接相关、未回答和假设；如果原文没有回答问题，写“未回答”，不要把相关性写成因果结论。
- 只在信任边界校验用户输入、连接器返回和原文内容；内部已由类型和回执保证的值不重复添加防御分支。错误向父会话抛出并保留可诊断信息。
- 任务结束时报告本批数量、成功读取数量、`未读到原文` 数量、输出文件路径、知识库沉淀状态和下一批范围。不得把局部批次描述成完整系统综述。
