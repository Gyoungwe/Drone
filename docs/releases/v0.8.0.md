# Percho v0.8.0 — 任务工作台：可验收、可选择、可归档

v0.7.8 交付了执行检查点与安全续接；v0.8.0 在此基础上把"任务"变成一个可查看、可验收、可归档的宿主账本。它仍然只记录宿主可观察到的事实，不代替科研判断。

## 本次交付

- **结构化里程碑与依赖**：模型通过 `task_plan` 提出有序里程碑和 `dependsOn`，验收条件是不可变合同，须由用户在任务面板确认。验收只承认四类依据——宿主文件回读（大小 + SHA-256）、限定范围的人工核对、Wiki 审核记录、Zotero 只读条目身份；模型自称完成不算数。
- **跨任务选择**："继续""下好了"等续接语在存在多个未完结任务时要求用户先选择，不猜测；任务切换不能接管正在进行的操作。
- **人工动作按事项解决**：`task_wait` 产生的文件/下载/授权/审核事项各自独立；核对一个文件只解决对应事项，取消不是同意，授权卡片不能授予权限。
- **任务归档**：已完成、已取消、部分完成或受阻且没有未知副作用与待处理事项的任务可以归档。归档任务不再参与续接和选择；任务历史满时只移除最早的归档任务，未结任务永不被静默丢弃。建议归档前先"导出检查点"。
- **未知副作用必须对账**：重启后仍为 `started` 的操作变成 `unknown`，任务进入受阻状态；用户需在目标系统核对后声明结果，宿主不重跑写入、安装或上传。
- **PDF 身份识别**：在受限 worker 内解析 PDF 前三页文本，核对请求的标题 / DOI；伪装成 PDF 的 HTML 落地页会被拒绝，加密或无法解析的文件要求人工检查。
- **Zotero 只读对账**：只查询精确条目身份，区分附件元数据与内容；条目数量（0、2、101）都不会被当作"导入完成"。
- **证据恢复**：被上下文淘汰的文件窗口只能在当前权限与文件版本核验通过后恢复，每任务最多两次、有字节上限，不生成新的科研证据回执。
- **Desktop 与 LAN 同一投影**：Desktop 任务卡可确认验收、核对文件、归档；LAN 网页显示同一份 `taskView` 的只读摘要（目标、状态、阶段、验收进度、待处理数量），不暴露路径与哈希，也不能发起任何操作。

## 信任边界

任务状态"记录的验收已满足"表示宿主观察到了约定的产物或人工核对记录，不是科学结论、整体正确性或发布证明。Wiki 候选仍需经审核入口发布；权限与科研证据必须按当前环境重新核验。`PERCHO_TASK_WORKBENCH=off` 可回退到 v0.7.8 的检查点运行时，旧记录以"未审阅的历史"方式导入，不会被改写。

## 修复

- Windows 上 pdf.js 要求 `standardFontDataUrl` 为带尾斜杠的 file URL，此前以 `path.sep` 拼接导致所有 PDF 解析失败；pdf.js v6 的 `destroy()` 位于 loading task 上，已兼容。
- 知识库 UI smoke 脚本中任务段落遮蔽了模块级 `actions` 数组。

## 验证与范围

本地 Windows 验证：lint 无错误（既有建议级警告保留，未禁用规则）、类型检查、全量测试通过、应用构建通过。新增回归覆盖归档前置条件、归档任务不参与续接、容量回收只移除归档任务、以及重启后账本恢复。

尚未纳入本版：多分支并行恢复、跨会话任务迁移、除 Zotero / Wiki 之外外部服务的结果对账。安装包仅由 GitHub Actions 构建发布；自动化验证不等同于真实科研任务效果验证。
