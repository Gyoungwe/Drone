# Drone v0.33.3

This release candidate hardens the unsigned desktop release pipeline after the
v0.33.2 macOS asset audit. The release workflow now validates the actual DMG,
ZIP, and Windows installer payload after each build, uploads them to a draft
release, downloads the uploaded assets again, verifies their SHA-256 bytes
against the build manifest, and only then makes the release public.

The release jobs build both macOS architectures in one invocation. This
removes duplicate staging and renderer work and gives `latest-mac.yml` one
producer, avoiding silent metadata overwrite when artifacts are merged.
Electron and electron-builder caches are keyed by platform and package locks;
build and full candidate validation run in parallel. Each build rejects files
outside the release allowlist, and the upload gate checks installers,
blockmaps, and updater metadata with an exact two-way manifest comparison.

The local macOS arm64 and x64 v0.33.3 artifacts were built with
`CSC_IDENTITY_AUTO_DISCOVERY=false`. Both ZIPs passed native `ditto` extraction;
both DMGs mounted read-only with `hdiutil`; each extracted app reported version
`0.33.3` and contained `Contents/Resources/app.asar`. Evidence is in
[`v0.33.3-asset-validation.json`](v0.33.3-asset-validation.json).

GitHub Release run
[`39191569111`](https://github.com/Gyoungwe/Drone/actions/runs/39191569111)
passed on both runners. The Windows x64 installer and ZIP passed build-time
validation, upload, draft-release download, ZIP payload inspection, and silent
NSIS installation; macOS arm64/x64 assets passed the corresponding DMG/ZIP
checks and byte-for-byte manifest comparison. The release remains unsigned by
design; signing certificates are not a gate.
