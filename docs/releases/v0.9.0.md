# v0.9.0

One authorization per task. A workbench task now asks the user once, up front, and then runs to delivery instead of interrupting for every write and every stage.

## One task authorization

After bounded read-only discovery, `task_plan` proposes the original goal, a plain-language scope summary, the existing write directories and immutable acceptance milestones in a single card. The **确认一次，执行到交付** action approves the acceptance criteria and the execution budget and starts the task — there is no second Continue click.

Consent is bound to a contract hash over the task id, goal, binding, scope summary, directory list and acceptance milestones. It does not transfer to another task, session or branch, a changed contract revokes it, and restoring a session never starts one automatically.

## Scoped write consent

Ordinary `write`/`edit` calls under the approved canonical directories and their children no longer prompt. This replaces only the default whole-tool `ask`. Everything else keeps its existing gate:

- explicit `deny` rules and pattern-specific asks
- command/shell confirmations — this is not a new arbitrary-shell or fullAccess privilege
- credentials, permission/trust/model configuration, private keys and VCS internals
- canonical path or symlink escape out of the approved roots, and hard-linked write targets

Approved roots must be existing project directories; a drive root, the home directory and its parents are refused. Missing output subdirectories may be created.

## Automatic stage progress

Stages advance on observed progress only — successful results of host-allowed, distinct non-control calls. Status/todo spam, failed checks and fabricated result events do not count. Recovery is limited to 3 host-triggered turns inside the unchanged 192-call lifetime ceiling, refuses unresolved side effects and never blindly replays a write. A recoverable blocked publication continues through a nonce-checked host message, not a forged user turn.

## Allow all for this task

If a command confirmation still appears during an authorized task, the approval dock offers **本次任务全部允许 / Allow all for this task** (`allowRun`, shortcut `T`). It approves every remaining confirmation in the current agent run, drains the queue and expires at `agent_end`. It is not persisted, is not remembered by pattern and never overrides a `deny` rule.

Together the two mechanisms give the user at most one authorization card plus at most one command prompt per task.

## Interruption budget

The research workflow skill now front-loads every user decision into one message, decides mid-task with documented defaults, and reports the defaults it took under 我替你决定的.

## Notes

Hard limits, missing credentials, absent user data and unrecoverable errors are reported with actual outputs and the specific remaining blocker instead of repeated stage approval requests. See `docs/task-authorization.md` for the full boundary list. This is source-level behavior: rebuild and restart the desktop app to load the changed bundled code.
