# Percho v0.7.4

Feature + reliability release. Zotero gets its own UI surface and is no longer entangled with Obsidian setup, and a runaway knowledge tool-loop can no longer burn a whole turn with no answer.

## Added

- **Zotero panel** with its own entry: a Zotero button sits next to Obsidian in the project sidebar and opens a dedicated panel (as a Settings category, mirroring the Obsidian entry). The panel shows live status (MCP registered / enabled / local API reachable / Zotero desktop detected), an **enable/disable toggle** for the Zotero MCP server, one-click connect/install (`/zotero-setup`), open Zotero / docs / download, and a cross-reference to the Obsidian knowledge panel. New read-only `getZoteroStatus` IPC backs it.

## Fixed

- **Runaway knowledge tool-loop.** A weak model could ignore the advisory per-turn tool budget and keep calling `research_read_knowledge` / `research_search_knowledge` for minutes, then hard-stop with a misleading "知识库检查未通过 … 请开启新一轮任务" and no answer — even for a trivial question. The publication gate now force-ends a turn at a per-turn tool-round cap (much earlier than the old 64-round / 4 MB backstop) with an accurate, actionable notice: it explains the assistant kept calling tools without answering and says to simply send another message (no new conversation needed).

## Changed

- **Zotero / Obsidian setup untangled.** The Obsidian "Setup" button is now Vault-only; the combined `includeLiterature` path is removed across renderer, backend and the setup extension. Cross-reference guidance points literature setup to the Zotero panel. The `zotero` entry in `~/.pi/agent/mcp.json` is unchanged — it was already the correct, separate location.

## Validation scope

Local acceptance targets macOS Apple Silicon with isolated application data, project and Vault. The release workflow builds other platforms separately; a tag does not by itself mean those builds have succeeded. Scripted loopback providers exercise real renderer input, IPC, SDK and file-writing paths; these tests do not establish real-model research quality.

## Distribution notes

macOS uses ad-hoc signing and is not notarized. No credentials or user Vault data are bundled.
