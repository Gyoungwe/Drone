## Required gates

The release workflow's `validate` job intentionally mirrors the main CI
static and desktop gates. It checks generated resources before tests and
checks the packaged MCP staging boundary before the production build.

```text
npm ci
npm run stage:pi-packages
npm run lint
npm run typecheck
npm run check:arch
npm run test:arch
npm run check:plugin-api
npm run check:extensions
npm run check:knowledge-runtime
npm run check:tasks-runtime
npm run check:research-runtime
npm run test:research-packaging
npm test
npm run test:upgrade
npm run check:pi-packages
npm run build
```

The `stage:pi-packages` step is idempotent and runs once before the read-only
`check:pi-packages` gate. The workflow does not run a publish, upload, or
external side-effecting release command during validation.

## Generated resource baseline

The candidate commit must include generated artifacts whenever their source
dependency graph changes. These checks caught stale resources in `v0.26.0`:

The versioned [gate manifest](v0.26.1-gate-manifest.json) is the source of truth
for this candidate's required commands and expected release assets. The release
workflow validates the candidate ref before it creates `v0.26.1`.

- `.pi/extensions/.build-manifest.json` and the six extension bundles whose
  input hashes changed;
- `.pi/lib/tasks/.build-manifest.json` and `.pi/lib/tasks/runtime.mjs`;
- `.pi/lib/.build-manifest.json`, `.pi/lib/source-archive-core.mjs`,
  `.pi/lib/research-loop-core.mjs`, and `.pi/lib/zotero-write.mjs`.

Regenerate them with:

```text
npm run build:extensions -- --force
npm run build:tasks
npm run build:research
```

Then rerun the corresponding `check:*` commands and review the generated
diff as part of the candidate commit.

## Publish gates after validation

After the single Windows validation job passes (and the candidate manifest records the same commit), the normal release workflow may
prepare the draft release, build the configured platform artifacts, verify the
required assets and publish the draft. The tag and release asset manifest
must reference the same commit that passed validation.
