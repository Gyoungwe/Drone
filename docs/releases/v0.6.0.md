# Drone v0.6.0

This release turns Drone's research workspace into a first-party, distributable knowledge workflow instead of a developer-local setup.

## Highlights

- Application-wide Obsidian knowledge Vault with guided setup, project scoping, incremental SQLite/FTS indexing, maintenance UI, and read-first retrieval.
- Evidence-aware answer publication checks: relevant Wiki reading, real search, source/version receipts, explicit blockers, and preserved completed artifacts when a final answer is withheld.
- Reviewed Wiki synthesis with human diff review plus optional, user-triggered isolated model review. Model approval is not scientific verification.
- Five protected knowledge roles: navigator, evidence curator, Wiki editor, Show Me explainer, and Wiki reviewer; bounded context and least-privilege capabilities keep their work out of the main transcript.
- Multi-round topic accumulation: one pending Wiki revision per exact topic, versioned evidence, and presentation-only Show Me archives in the knowledge library.
- Ordered public execution timeline: stage summary → tools → next summary, without exposing raw private chain-of-thought.
- Per-turn and session SDK token usage, cache-hit summaries, and separate Wiki-review usage receipts.
- Packaged research-workbench manifest so source builds and installers load the same first-party research extensions and skills in unrelated projects.

## Research delivery

- Built-in `research-vault`, `research-workflow`, and `research-show-me` skills ship with the application.
- Source archiving distinguishes papers, supplementary files, software, and manuals and records provenance/hash information.
- Software/manual delivery now distinguishes landing pages from actual command/parameter references and separates author-reported performance from local tests.
- Show Me output is searchable as a presentation layer but is excluded from scientific evidence receipts and Wiki evidence chains.

## Safety and review boundaries

- Wiki model review is foreground, opt-in, and advice-only by default; auto-apply is scoped to one exact candidate and requires all host checks to remain current.
- Child-agent reads never mint parent publication receipts. The main answer still has to read and cite the sources it relies on.
- Generated Wiki/Show Me content remains explicitly distinct from scientific verification and protected human text.
- Runtime bindings, model credentials, private Vaults, downloaded literature, sessions, browser logins, and the developer's personal skill directory are not shipped.

## New-user setup still required

Users provide their own model credentials, Vault, project trust decisions, optional search/MCP adapters, literature subscriptions/logins, and local scientific software environments. Shipping the workflow does not copy the maintainer's accounts or execution environment.

## Validation

- Repository lint, typecheck, full tests, and build pass locally before release preparation.
- 1,102 tests pass: backend 730 + desktop 372.
- Fresh arm64 DMG mount/copy/first-launch was tested with isolated HOME, userData, agentDir, and knowledgeDir.
- A real isolated `gpt-5.6-sol` Wiki review was run against a disposable Vault in advice-only mode; it left the Wiki unwritten and the parent conversation unchanged.
