# v0.10.0

Percho is now Drone. The rename covers the product name, the package names, the user directory and the plugin API, and a task can no longer dead-end on a provider 400 in the middle of a tool call.

## Renamed to Drone

The application, the executable and the published packages are now `drone`:

- app id `io.github.gyoungwe.drone`, product name **Drone**, executable `drone`
- packages `drone` and `@drone/{backend,shared,desktop}`
- environment variables `DRONE_*`
- user directory `~/.drone`
- plugin API `window.DroneUI` / `DroneUiApi`, manifest key `droneUi`, types `drone-ui.d.ts`, skill `drone-ui-plugin`
- release artifacts `drone-mac-<arch>.dmg`, `drone-windows-x64.exe`, `drone-linux-x64.AppImage`

The repository moved to `Gyoungwe/Drone`. GitHub redirects the old name, so existing clones keep working.

## Upgrading

The new app id means a new userData directory, so **previous sessions, settings and installed plugins are not carried over**. This is a deliberate clean break.

On first launch the app moves `~/.percho/daily` to `~/.drone/daily` so the daily workspace — real user output — survives the rename. The move only happens when the target does not exist; a cross-device or locked rename falls back to linking the old path, and any failure is logged without blocking startup. The original data is left in `~/.percho` either way.

`~/.percho/ui-plugins` is deliberately not migrated: it is a link into the old userData directory, which the new app id recreates from scratch.

Settings and plugins under the old `%APPDATA%\@percho` / `~/.percho` locations must be reconfigured by hand.

## Fixed: task aborted with a provider 400

A task could dead-end with `400: Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`, and every Continue click reproduced it immediately.

A stage checkpoint could fire from inside the `tool_call` hook and insert a task status card between an assistant message carrying `tool_calls` and its tool results. That pairing is mandatory for OpenAI-compatible endpoints, so the provider rejected the whole turn at the entry point, and the stage counter never reset.

Status cards are now held while any tool result is outstanding and flushed once the last one is paired, or at `agent_end` at the latest, so no status is lost. The counter is reset when a turn starts and ends, so an errored or aborted turn cannot strand a held card.

## Notes

This is source-level behavior: rebuild and restart the desktop app to load the changed bundled code.
