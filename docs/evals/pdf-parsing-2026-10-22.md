# PDF 解析质量评估与集成取舍（评估数据：2026-10-22；决策：2026-10-23）

本次评估使用 fixtures/pdf-hard/manifest.json 中的 10 篇开放获取论文，覆盖双栏、公式密集、跨页表格和扫描版派生样本。可重跑命令：node scripts/eval-pdf-parsing.mjs。

- 当前默认的 pdf.js 成功解析 10/10 篇，正文字符召回均值 80.0%。表格、公式和参考文献指标见同目录 JSON。
- MinerU：10/10 `unavailable`（`mineru` 命令不可用）；GROBID：10/10 `unavailable`（未设置 `GROBID_URL`）。这两项没有产生可比较的质量指标，因此不能据此宣称它们优于 pdf.js。本轮未安装、未集成、未把它们作为默认后端。
- 扫描版样本的 pdf.js 文本召回用于暴露 OCR 缺口；OCR 质量和表格结构仍需人工抽样复核，不能把启发式分数当作论文事实。

## 集成决策

本轮**保持 pdf.js 为默认解析器，暂不集成 MinerU 或 GROBID**，因此 PR6 关闭为“评估完成、可选后端未接入”。理由是：pdf.js 已在 10/10 样本上完成可重跑解析，主要缺口集中在扫描件 OCR；MinerU/GROBID 在本机均不可用，尚无受控质量对照；把未测量的后端加入默认流程会扩大安装、运行资源和故障回执边界，但不能改善已证实的结果。

若后续确实需要可选后端，必须另开集成任务，先补齐人工逐页参考文本、固定 MinerU/GROBID 版本和输入/输出适配器，再分别评估本地服务与 API 的资源、超时、失败回执和安装体积；候选后端应保持 opt-in，不进入默认安装包。
