# P4 任务迁移交接（2026-10-29 下午）

接手者：先读仓库 `AGENTS.md`、[`docs/INDEX.md`](INDEX.md)、本文，再读下面列出的三份设计。上一份总交接 [handoff-2026-10-29.md](handoff-2026-10-29.md) 的仓库/分支表已经过时（新架构已在 #240 合入 main）；其中的约束和背景仍然有效。

## 1. 目标与当前位置

总目标不变：Drone 是通用 Pi 桌面宿主，科研功能全部来自可安装、可停用的标准 Pi 包；卸载科研包后 Drone 仍能构建、启动和聊天；最终是一个好用、功能贴切的科研智能体。执行清单是 [P0–P7 计划](pluginization/native-plugin-implementation-plan.md)（含 2026-10-29 用户确认的执行方式修订）。

P4 = 把任务插件（`@gyoungwe/pi-core` 的任务状态机）从“启动期进程内 taskHost”迁到受管插件运行时，并删除宿主里的启动期 taskHost/coreHost 装配。分四步：

| 步骤 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 宿主签发的任务授权（一次宿主对话框） | ✅ main（Drone #241） |
| 2 | 宿主配套能力：自动续作、状态卡、按当前读权限读工作区；只读 hook 可用的簿记/提问 | ✅ main（Drone #242，`838362de`） |
| 3 | 插件侧：原生 Pi 与受管运行时共用一个 workbench adapter | 🟡 drone-plugins PR #2（分支 `claude/p4-task-managed`，`0faa85f`），**未合并**，CI 结果需核对 |
| 4 | 补齐受管路径缺口 → 安装包真实验收 → 切换清单 → 删除启动期 taskHost/coreHost 与旧桥 | ⏳ 未开始（用户要求本次停在第 3 步） |

## 4. 第 3 步做了什么（插件 PR #2）

- `packages/pi-core/src/task-runtime/workbench-adapter.mjs`：任务编排（hooks、工具、命令、续作、进度）唯一实现；两宿主的差异全部是 ports。
- `native-adapter.mjs`：原生 Pi/进程内宿主的 ports（行为与之前一致，原有测试全过；一个假定时器测试多 flush 了一个微任务）。
- `managed-application.mjs`：受管运行时的 ports，映射到宿主能力：
  - 记录 `session.records.read/append`；状态卡 `session.notify {content, view}`；提问 `session.select/input`；空闲 `session.inspect`；
  - 任务授权 `task.grant.current` → 没有当前授权时 `task.grant.request`（替代插件自己的“开始执行这个任务？”选择框；`maxCalls 192`、`maxAutoResumes 3`、`contractHash` 来自 `consent.mjs`）；
  - 续作 `task.continue`，`inlineHandoff: true`：受管插件只在调用期间有 live caller，所以续作在 `agent_end` 调用内完成，不用定时器；宿主用 followUp 排队；
  - 文件验收 `workspace.readFile` + `inspectTaskBytes`。
- 受管的全部 hooks/工具/命令都声明 `read`（见设计“只读 hook 也能做的事”），普通聊天不弹窗。
- 测试：`packages/pi-core/test/task-runtime/task-managed-adapter.test.mjs`（效果声明、一次宿主授权、拒绝、续作、重开后需要新授权）。pi-core vitest 219/219；`node --test test/packed-types.test.mjs` 本地需要 `DRONE_PLUGIN_API_TARBALL`（CI 会设置）。

## 5. 接下来按顺序做

### 5.1 收尾第 3 步
- 核对 drone-plugins PR #2 的 CI；通过后合并（用户已授权合并）。
- Drone 侧更新 `plugins.lock.json` 的 pi-core（以及同一 commit 下其他包的哈希，如有变化）并跑全量门禁。
- 注意：Drone 的 `@gyoungwe/plugin-api` 在 #242 给 `PluginSessionNotifyInput` 增加了 `view?`；插件侧目前用 JS，不依赖新类型。若插件要用新类型，需要按现有方式提供新的私有 API tarball（`DRONE_PLUGIN_API_TARBALL`）；**不要 npm 发布**（未授权）。

### 5.2 补齐受管路径的已知缺口（切换前必须解决或经用户明确取舍）
1. **PDF DOI/标题身份核对**：`pdf-identity.mjs` 用 `worker_threads`，受管进程没有 `--allow-worker`（`packages/backend/src/plugins/process-runtime.ts` 约 286 行），且 `pdfjs-dist` 需在包根内可解析。可选：受管时在进程内直接解析（整个进程已隔离）、或宿主提供通用 PDF 文本能力。
2. **Vault（知识库绑定）文件验收**：受管 ports 的 `readKnowledgeBinding` 目前返回 null，`rootKind: "vault"` 会拒绝。需要通过知识插件声明的服务（`provides/requires`，见 `plugins/service-capabilities.ts`）读取绑定与只读文件，不能让宿主重新解析 Vault 数据。
3. **其他插件注册的验收器**（例如 Zotero 文献核对 `zotero-literature`，示例任务依赖它）：进程内版本靠 `pi.events`；受管版本需要设计里的跨插件“验收器角色”，在提供者 owner 内执行，复核来源与会话。先写设计给用户确认。
4. **决策记录、宿主能力检查点、上下文淘汰事件**：受管插件目前收不到 `drone:decision-record/v1`、`drone-capability-checkpoint-v1`、`drone:context-evicted`。决策记录可考虑通用的宿主能力；淘汰事件缺失只会让证据恢复不可用（不影响正确性）。
5. **`sendUserMessage("继续")`**：受管时改为状态卡提示用户发送“继续”；如需更好体验，有授权时可改用 `task.continue`。

### 5.3 第 4 步：切换与删除（每项都要真实证据）
- pi-core 清单：增加 `entrypoints.desktopRuntime`（`dist/managed-runtime.mjs`）、`drone.taskGrants: "request"`、`drone.workspaceRead: "session"`，同步插件仓库 `scripts/check-manifests.mjs` 与 `docs/PLUGIN-SPEC.md`；官方 Pi 格式检查必须仍然通过。
- 真实 SDK + 安装包验收（Drone `test/` 下新建，参照 `test/task-grant-sdk.test.mjs` 和 `test/example-tasks-one-authorization-sdk.test.mjs`）：一次宿主授权后示例任务完成且写后回读；普通聊天零插件弹窗；两会话隔离；关闭一方不影响另一方；停用包后工具/命令/hook/UI 同时消失；重开会话需重新授权；升级/回滚不继承旧授权。

## 7. 环境与流程上的坑

- **GitHub**：本环境不能用 GraphQL（`gh pr create` 会 403），用 REST：`gh api repos/Gyoungwe/<repo>/pulls -f base=main -f head=<branch> -f title=... -F body=@file`；合并 `gh api -X PUT repos/.../pulls/<n>/merge -f merge_method=merge`。
- **root 运行的测试**：`execution-runner.test.ts` 与 `state-reservations.test.ts` 各有一项依赖 chmod 故障注入，root 下必失败，CI（非 root）通过。
- **桌面构建 OOM**：容器里 `npm run build` 可能堆内存不足，用 `NODE_OPTIONS=--max-old-space-size=6144`。
- **Windows CI**：三个 Windows job 在 main 上就失败（`continue-on-error`），原因记录在 `docs/PITFALLS.md`；判断 PR 时只看 macOS/Linux。新测试若用 `os.homedir()`，同时 stub `HOME` 与 `USERPROFILE`。
- **本地工作树**：Drone `/home/claude/repos/Drone-int`，插件 `/home/claude/repos/plugins-int`（均为工作树；共用 stash，不要用裸 `git stash`）。
- **受管插件机制要点**：调用结束后 broker 不再借出能力（定时器里调用会失败）；创建会话时没有 live caller；`session_shutdown` 不经过 broker；只读调用只能用 `readCallable` 的写能力。
