# 主机选择器与科研计算卡片

## 目标

把“主机”从一张需要填写大量 SSH 字段的设置表，改成研究工作台里的三步入口：发现本机已有的 SSH 配置、选择一个远端研究主机、再检查环境并进入可复现运行方案。手动表单保留给没有写入 `~/.ssh/config` 的特殊节点。

## 页面布局

1. **远程研究主机**：顶部保留主机数量、最近健康检查和刷新；每个已登记主机卡片先显示连接状态、平台、工作区和延迟，检查环境、预览方案、打开终端、移除等动作放在卡片底部。
2. **从本机 SSH 配置选择**：主卡片直接读取 `~/.ssh/config` 的 `Host` 别名，显示 `user@hostname:port`、身份路径数量和“加入主机”。加入动作只把别名、HostName、端口、用户、第一条 `IdentityFile` 和 `ProxyJump` 作为主机配置交给后端；不读取私钥正文，也不把密钥内容写入 UI 或 JSON。
3. **手动登记或调整高级设置**：默认折叠。只有需要自定义工作区、跳转主机、主机指纹或覆盖身份路径时才展开；连接仍经过远程操作审批。
4. **作业与科研状态**：主机卡片下面继续显示运行中的作业、阶段/任务计数、失败原因、MultiQC 链接和初始化检查，形成“选择主机 → 检查环境 → 预览方案 → 运行”的单一路径。

## 数据和安全边界

- 主进程通过只读 IPC 返回脱敏的 SSH 主机元数据；renderer 只调用 `window.pi`，不接触文件系统。
- 解析器只打开 `~/.ssh/config`，不打开 `IdentityFile` 指向的私钥；缺少配置或没有可选择的具体 `Host` 别名时返回空列表。
- 发现结果是临时选择列表；用户点击“加入主机”后才进入现有 backend `JsonStore` 主机配置。私钥、密码、token 和会话正文不会持久化。
- 远程探测、提交、终端和写入继续走现有逐次审批，不因自动发现而获得连接权限。
