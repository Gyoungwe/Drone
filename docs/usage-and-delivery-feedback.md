# SDK usage UI and useful delivery failures

This iteration reuses the installed Pi SDK's response `usage` and `getSessionStats()` API. It does not install a new extension, add a tokenizer, pricing table, billing database, network poller or metering model. The backend only forwards existing cache/total fields and preserves message usage through the display adapter.

The per-turn UI groups existing reported responses between user messages, including failed/blocked responses and hidden control-tool requests. Snapshot IDs deduplicate `message_end`/`turn_end`; text/tool display splitting assigns usage once. Output already includes reasoning tokens. Cache ratio is cacheRead / (input + cacheRead + cacheWrite), weighted by tokens. Missing cache fields produce an unknown ratio; a zero cost report is not shown as free.

The composer footer queries the existing stats IPC at session/committed-message/settled changes with a 150 ms debounce, never per token. SDK session totals may include old branches, compaction and tools which explicitly report usage. Independent child calls or external tool charges absent from SDK statistics are not fabricated or silently included. The UI documents this scope.

A separate public progress note is derived from the existing set_status tool's successful result, including optional detail/next fields. Raw private reasoning remains withheld. Tool-derived operational reports and preflight errors are distinct from scientific conclusions.

`research_check_answer` calls the same final check, returns specific missing paths, and never mints a read receipt. `research_task_status` exposes bounded observed artifacts and failures. A failed final answer is replaced with an operational report, not just a generic blocker and never an unchecked draft. Controlled Show Me and run-summary outputs get host-only versioned delivery receipts; they can be linked as outputs but never counted as evidence.

The observed RNA-seq task reached the answerable research stage, wrote a report, three script templates and a workflow explainer, and saved its summary; the final public response was blocked with source-unread. The old proof did not retain the offending path, so it does not establish which particular citation caused that run's failure. The generated-output/evidence confusion is independently reproduced and covered by new tests. Source fetch timeouts, absent rg/apply_patch and binary PDF transport also occurred. This change stops obvious PDF binary transport and propagates explicit structured tool failures; it does not assert that the biological report or scripts are scientifically validated.

Read-only replay of the actual failed RNA-seq conversation through the new display adapter: 31 reported main responses; uncached input 2,573,829; cache reads 656,640; cache writes 0; output (including reasoning) 38,658; total 3,269,127; weighted cache rate 20.3264603375%. Two existing public set_status messages reappear as progress notes. The reported cost is zero without valid price information, so the UI does not present it as free. These are repeated requests over a whole turn, not a single context window. No source files or old conversation were rewritten during replay.
