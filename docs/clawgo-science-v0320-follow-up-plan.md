## 2. 证据边界

| 状态 | 当前可写入的主张 | 当前不能写入的主张 | 解除条件 |
|---|---|---|---|
| `verified` | NCBI 作业状态、原始响应、解析命中、序列长度、比对数字、脚本和文件哈希 | 这些计算结果等同于功能实验 | 保留原始响应、输入序列哈希、解析脚本和运行环境 |
| `observed` | ClawsGO 任务曾显示 6/6、交付卡、PDF 校验和一致性日志 | UI 步骤数本身证明科学结论 | 将 UI 观察与文件/日志分开登记 |
| `cross-species` | 人、果蝇、酵母文献可用于提出机制候选和判别预测 | 跨物种结果直接证明小菜蛾表型或免疫功能 | 获得小菜蛾直接实验数据，或明确标注为推断 |
| `inferred` | PxDHX16 可能属于 DHX16/Prp2 家族并参与剪接体相关过程 | “已经影响发育/应激”或“已证明通过剪接” | 小菜蛾 RNAi/遗传干预、剪接 readout 和表型之间的因果证据 |
| `unknown` | 小菜蛾中的表达、定位、RNAi 效率、单拷贝性、催化位点生化作用仍未知 | 把检索空白写成阴性结果 | 完成对应实验或可复核的直接来源 |

明确的未决项仍包括：

1. **没有 L1 证据**：没有小菜蛾 DHX16 功能干预、剪接组或发育/应激表型数据。
2. **直系同源仍是序列层面判断**：尚未做全蛋白组同源搜索、单拷贝检查和物种树；报告应使用“序列证据支持的候选直系同源物”措辞。
3. **催化位点映射不是功能验证**：G570/S398 只是跨物种坐标映射，构建失活等位基因前需要保守性、结构约束和功能分离验证。
4. **文献台账存在待核实条目**：凡没有原始文献直达链接的记录，只能作为线索，不能进入决定性证据集合。
5. **实验可行性未确认**：小菜蛾种群和饲养体系、RNAi 递送效率、已有未发表起始线索（P3/P2/P5）仍待用户或实验室确认。
6. **“未发现”不是“没有”**：当前检索空白只能记录检索范围、日期和查询式，不能宣称小菜蛾不存在相关功能。

## 3. 后续工作分层

### A0：冻结现有计算证据（现在可做）

目标是让这批外部交付可以被 Drone 的研究账本引用，而不把原始结果复制到代码仓库。

1. 保留 `cdsearch_QM3-qcdsearch-12D9BED96835D6CC-205C0C2D6241BC0D.txt`、解析 TSV、输入 FASTA、`04_cdsearch_provenance.tsv` 和 manifest 作为外部证据集合。
2. 在 Drone 的 evidence capsule 中只登记相对路径、SHA-256、来源接口、作业 ID、检索时间、解析脚本版本和 omission 清单；不登记会话正文、凭据、私人状态或不可复核的模型叙述。
3. 将证据状态标成 `observed`/`verified`/`reproduced` 三态：当前 CD-Search 是 `verified`（服务器返回成功且原始响应可读），重新执行脚本并比较结果后才可升级为 `reproduced`。
4. 对任何再次取回动作使用已有 `cdsid`；只有作业过期或服务端明确拒绝时才新建作业，并在 ledger 中建立新的 attempt，而不是覆盖旧记录。

验收：原始响应可解析、输入/输出哈希稳定、`analysis/08_verify.py` 通过、没有新增私有路径或会话正文进入仓库。

### A1：补齐计算稳健性（当前可支持）

这部分仍属于 in-silico，不改变“未做实验”的结论。

1. **同源关系**：对小菜蛾蛋白组做全蛋白组相似性搜索，记录候选旁系同源物、覆盖度和最佳 reciprocal hit；必要时构建包含果蝇、人、小鼠、酵母和候选旁系同源物的物种树。
2. **结构域**：保存 CD-Search 服务日期、数据库版本（若接口提供）和解析规则；将特异性命中与非特异性/超家族命中分层，避免把每个命中都当成独立结构域。
3. **位点映射**：对 G570/S398 进行多序列比对和结构域边界复核；在设计文件中把它们标为“待验证构建位点”，而不是已确认的催化残基。
4. **重跑差异**：若 NCBI 或 UniProt 返回内容变化，保留旧 attempt，新增带时间和版本的 attempt，并标记 `supersedes` 关系；不得静默替换现有交付。

验收：每项计算都有输入、命令、软件/数据库版本、输出哈希、失败状态和局限；结果变更能在 inquiry ledger 中追溯到具体 attempt。

### A2：直接文献和空白复核（需要谨慎推进）

1. 复核台账中所有决定性文献的原始链接、物种、系统、实验 readout 和 DOI/PMID；没有直达原文的条目保持 `lead/unverified`。
2. 对“小菜蛾 DHX16 功能研究”做可重复的限定检索，记录查询式、数据库、日期、命中数量和排除理由；报告为“在本次范围内未检出”，不写成不存在。
3. 将人/果蝇/酵母证据拆成“直接观察”和“用于设计预测的跨物种支持”，不得把跨物种文献提升为 PxDHX16 的 L1 证据。

验收：每条进入决定性证据集合的记录都有稳定标识符或可访问 URL；检索空白有范围和日期；无法核实的条目不会驱动唯一结论。

### B0：实验前置门禁（P2/P3/P5 确认后才能开始）

| 门禁 | 必须先确认 | 未通过时的动作 |
|---|---|---|
| `P3` | 小菜蛾活体种群、饲养条件、虫期和伦理/生物安全边界 | 只做计算与公开数据整理，不声称可开展 T1 |
| `P2` | RNAi 递送方式、阳性对照、敲低效率检测和批次稳定性 | 先做体系验证；不能把“无表型”解释为非必需 |
| `P5` | 是否有未发表转录组、筛选命中或既有候选靶标 | 若有，重新定义为验证性研究并冻结候选集；若无，保留探索性设计 |

只有三个门禁都通过，才进入设计文件中的 T1 剂量-时间爬坡。T1 的首个可判别窗口是残留表达 30–60% 的亚致死剂量；若找不到该窗口，H1（全局剪接）和 H2（选择性剪接）不能被强行区分。

### B1：因果判别实验（未来工作，不是当前结果）

继续沿用 ClawsGO 的竞争假设，但把判别条件写成执行门：

- **H0 方法学假象**：两条独立 dsRNA、dsGFP、未注射和阳性 RNAi 对照都必须通过敲低/损伤/一般毒性检查。
- **H1 全局剪接**：在亚致死窗口观察广泛差异剪接，且事件覆盖率随剂量单调增加；没有靶标异构体救援时才可支持该解释。
- **H2 选择性剪接**：差异剪接集中在预注册的功能类别/顺式特征，并且候选异构体纠正能部分救援表型。
- **H3 非剪接功能**：剪接缺陷的中介比例不足以解释表型，且免疫挑战或分离功能突变留下独立直接效应；人/鼠的免疫证据只能作为预测来源。

任何“支持 H1/H2/H3”的结论都必须同时给出效应量、置信区间、检测下限、阴性结果解释和未排除的 H0；不能只根据一张 RNA-seq 图或单个突变体下结论。

## 4. 与 Drone v0.32.0 的接入方式

v0.32.0 已提供足够的账本和证据基础设施，后续接入应保持以下映射：

| 外部 ClawsGO 记录 | Drone 研究状态 | 接入要求 |
|---|---|---|
| CD-Search attempt | `RunAttempt` / analysis evidence | 保存作业 ID、服务器状态、输入/输出哈希、时间和脚本版本 |
| 原始响应、TSV、FASTA | `Artifact` / evidence capsule | 内容寻址、来源链、可重放状态；不复制会话正文 |
| scope / hypotheses / design | `Question`、`Hypothesis`、`DecisionProposal` | 记录默认假设、待确认前提和采用/撤销原因 |
| 40 条证据台账 | inquiry evidence/claim 记录 | 保留 evidence level、source URL、物种、观察、局限、状态和父链 |
| manifest / verify.log | reproducibility receipt | 保存检查命令、退出码、文件数量和哈希摘要 |

导入前必须通过路径安全、文件大小、哈希和 omission 检查；导入只产生元数据和受控 artifact 引用，不把外部项目的会话文件、凭据、`results/` 或私有状态带入 Drone。

## 5. 下一次可交付的最小切片

下一个 PR/运行应只承诺以下可核验输出：

1. 一个只读的 ClawsGO evidence capsule manifest，记录 CD-Search、序列比对、位点映射和台账文档的哈希与状态。
2. 一份更新后的检索空白表，分别列出“已复核直接证据”“跨物种支持”“待核实线索”“未知”。
3. 一个计算重跑 attempt（优先复用既有 `cdsid`），有明确的 success/expired/failed 状态；重跑失败不覆盖已有成功结果。
4. 一份 P2/P3/P5 逐项确认表；在确认完成前不生成“已完成实验”或“可直接执行 T1”的措辞。

不在下一切片中承诺：小菜蛾表型结论、剪接因果结论、免疫功能结论、催化位点生化结论、实验样本已采集或任何湿实验结果。

## 6. 复核与完成标准

- **代码基线**：worktree 必须保持在 `v0.32.0` 之后的明确分支；`git fetch origin --tags`、基线 SHA 和变更范围写入 PR。
- **证据完整性**：原始输入、输出、脚本、版本、时间、哈希和失败/未知状态可回读；不存在只依赖模型叙述的关键结论。
- **科学边界**：所有小菜蛾功能主张必须能追溯到直接证据；跨物种结果标为推断；检索空白标为未知。
- **Drone 检查**：与本计划相关的文档变更通过 `git diff --check`；若实现代码，再按 AGENTS.md 执行 lint、typecheck、test、build 和 `check:arch`。
- **发布边界**：本计划只允许提交分支和 PR，不合并、不打标签、不发布安装包。
