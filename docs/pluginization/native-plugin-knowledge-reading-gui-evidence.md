## 真实观察

| 场景 | 结果 |
| --- | --- |
| 启动时拒绝后台权限 | 页面显示加载失败，领域/索引子进程均为零 |
| 拒绝后停用再启用 | 再次明确批准状态和两个数据根后成功显示知识页 |
| 当前 alpha 会话 | 分类和列表只有共享两篇与 alpha 一篇；beta 不出现在列表、链接节点或图谱 |
| 未启动会话的应用范围 | 只显示共享两篇；全库索引统计仍明确显示四篇，不冒充当前范围计数 |
| 阅读与分页 | 显示原文行号与 hash；继续读取同版本后页；合成源改变后明确拒绝旧 hash，刷新从新版本第一页读取 |
| 链接与图谱 | 双向链接可打开原文；图谱只显示三篇可见笔记，键盘选择节点后“打开笔记”进入正文 |
| 模型工具清单 | 实际模型请求包含 knowledge_status / knowledge_search；模型确实返回两项 tool call |
| 模型工具执行 | **失败**：旧任务守卫没有读取受管工具声明，两个只读工具均被误判为需先批准 task_plan。回执 isError=true，不以 GUI 的“2 次工具”统计或离线模型的总结文字代替成功证据 |
| 停用 | 两个知识子进程真实退出，宿主显示默认未绑定页面 |
| 停用后再次恢复 | 原生状态目录选择器的提交按钮持续不可用，本轮取消并保留可见取消错误，未记恢复通过 |
| 应用退出 | Cmd-Q 后日志显示 backend disposed，但主进程仍存活且窗口为空；保留失败，不能记完整关闭成功 |

本机原始截图、AX、模型请求元数据、工具回执摘要与进程清点存于 `.local/acceptance/native-plugin-knowledge-reading-gui-2026-10-26/`。正文不提交会话内容或本机状态。`manifest.json` 列出逐份证据指纹与失败状态。旧只读 DMG 的分类元数据缺失失败保留在前一轮目录，不覆盖。
