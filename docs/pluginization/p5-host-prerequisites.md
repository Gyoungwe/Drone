### 2.2 Confined byte-file transaction and 64 MiB staged reference

**Exists:** grant types at `packages/backend/src/plugins/file-capabilities.ts:27`, root/symlink confinement at `packages/backend/src/plugins/file-capabilities.ts:139`, and activation writer reservation/drain at `packages/backend/src/plugins/file-capabilities.ts:299`. Resource process draining and final lease release are separate at `packages/backend/src/plugins/resource-capabilities.ts:229`. Private resource storage is not permission to write adopted data. Limits are 1 MiB text (`packages/backend/src/plugins/file-capabilities.ts:70`), 4 MiB binary state (`packages/plugin-api/src/node/binary-state.ts:6`) and 8 MiB file snapshots (`packages/backend/src/plugins/stable-file-bytes.ts:7`).

**Gap:** byte staging, bounded chunk transport, immutable file refs and confined blob/branch transactions are **absent at base**. Evidence currently performs host IO directly: stable reads at `packages/backend/src/services/analysis-evidence.ts:113`, blob writes at `packages/backend/src/services/analysis-evidence.ts:403`, branch materialization at `packages/backend/src/services/analysis-evidence.ts:480`. Its logical cap is `packages/backend/src/services/evidence-attestation.ts:4`; import additionally allows twice that serialized size at `packages/backend/src/services/analysis-evidence.ts:458` (D2).

**B0 contract; D2 = A and D9 = A decided 2026-11-18:** retain 64 MiB (67,108,864 bytes) decoded and 2x / 128 MiB (134,217,728 bytes) serialized. There is no separate per-chunk cap. `STAGED_DECODED_LIMIT` and `STAGED_SERIALIZED_LIMIT` mirror those backend sources in API `src/p5-staged-transport.ts`, re-exported through `p5-evidence.ts`. `StagedOpenInput` declares decoded `bytes` and a path relative to the host-selected approved root; JSON cannot select a root or supply a grant. `StagedChunkInput` carries `fileRef`, decoded `offset` and canonical padded base64. Offset plus decoded chunk length must fit both the decoded total and the declared object size; the host measures the entire serialized chunk message, including its envelope, against the 2x allowance. A chunk may span the entire decoded total; text/binary-state/snapshot limits do not apply.

Accepted byte ranges are half-open and immutable; overlap is `STATE_CONFLICT`. Seal requires complete range coverage plus matching host hash/size readback (`READBACK_FAILED` on hash mismatch); resealing with changed hash/size is `STATE_CONFLICT`. `StagedRefInput` is the closed lookup/cancel shape; lookup only returns sealed immutable `StagedRef` metadata. B1 must bind refs to actual caller/source generation, workspace/session, action, root and file identity outside JSON. Cancellation aborts owned work and yields `CANCELLED`; caller completion/switch, disable, reinstall, revocation and host restart invalidate open and sealed refs (`SCOPE_CHANGED`). Invalid refs require a new open under current consent, never restored approval. Bounds yield `LIMIT_EXCEEDED`, malformed input `INVALID_INPUT`, and escaping paths `PATH_ESCAPE`. Pure validators consume host-owned context and measured wire size; they perform no byte IO or authorization. B1 owns transitions, confinement, cancellation and restart enforcement.

**Proposal:** specify bounded open/chunk/seal/read schemas in B0 before runtime dispatch; no large inline capsule across provider JSON. Host creates a ref bound to approved root, file identity/hash/size, caller/source generation and action. A copied ref confers no authority. Host-owned staging uses only invocation-owned temporaries; final blob/branch writes require S for the exact adopted roots, CAS/lease, confinement recheck and readback. Input reads require existing read consent; output export separately requires C. Keep roots in place, drain old writers, retain data on disable/uninstall, and require explicit re-adoption. Never use `state.writeJson` for arbitrary byte files. **New:** B0–B3 modules; dependencies A2, R1, D2, then Z1. No size-limit increase to the existing small ports.
