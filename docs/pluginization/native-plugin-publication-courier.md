# Native publication identity courier

This is a mechanism slice under the approved [publication design](../superpowers/specs/2026-10-28-managed-native-publication-design.md). Full P2, installed-source policy, the real knowledge consumer and the formal installer remain incomplete.

`PluginNativeSession.projection` retains its existing event/snapshot methods and adds `finalize(event, PluginRuntimeContext)` and `finalizeEffect` (default write). The installed native worker executes finalization in the actual owner. Pure event/snapshot projection receives no active capability context. Neither method grants filesystem/model authority merely by projecting in-memory state.

`process-runtime` sends references in a private native RPC envelope, outside SDK messages and plugin operation DTOs. Every native attachment has a parent WeakMap and a child originals Map that is destroyed with that attachment. Only actual returned RPC objects and the SDK message that the current `message_end` invocation will replace in place are associated. A JSON clone or a visible proof/reference property cannot register an association. A fingerprint may reject a changed object; matching bytes never register an unfamiliar object.

The worker restores an original only from that envelope, then invokes the real owner's projection. It never manufactures the owner's WeakSet membership. An actual child proof object is retained for this attachment's lifetime. A separate attachment has a separate object store and separate owner proof state. Cancellation waits for the actual child invocation cleanup, checks the real signal again before issuing/remembering references, and rejects a late result.

The actual restricted-worker/SDK test creates a synthetic publisher whose decision depends on its own WeakSet. The real pinned SDK boundary publishes the actual checked object; subsequent actual-object projection/snapshot succeeds. An identical JSON clone, copied visible ID/reference, another attachment and a modified same SDK object are blocked. The attachment is revoked on disposal. This fixture proves the mechanism; it does not establish a real knowledge evidence check, actual source discovery, registry approval, UI integration or full workflow acceptance.

Validation: the combined actual SDK suite passed 25 tests (delivery fence 9, courier 1, existing native owner 4, tool protocol 4, command protocol 7). Parent association behavior passed 2 additional unit tests. Backend typecheck, plugin API build, architecture (0 findings), targeted Biome and whitespace checks passed. Logs: `/tmp/native-delivery-mechanisms-sdk-final.log` and `/tmp/native-delivery-courier-tsc-final.log`.

Boundary-check accounting: the added object/array tests are confined to native JSON transport or untyped plugin exports. Parent encode accepts unknown SDK event carriers; parent remember validates the actual returned message and reference list; worker retain validates the plugin-returned carrier/message; worker restore validates the private envelope's array correspondence; native attachment validates untyped projection functions. These checks prevent associating a primitive/mismatched message or accepting an unusable projector. The default finalizer write effect is an authorization rule; it does not conceal invalid empty-string declarations. No new retry, timeout, compatibility fallback or process-global authority ledger is added.

## Real caller, cancellation and UI-only lifecycle follow-up

Pure `event` and `snapshot` now accept an optional real AbortSignal, preserving their existing call forms. The signal is created in the owner process and is never serialized. A held actual worker projection observes its own cancellation, completes cleanup, and only then rejects in the parent; a sibling projection and later use of the same owner stay live. The registry removes ambient capability authority for pure projection. Finalization instead borrows the true bound session caller through a host-only facade, with default write approval. Caller/session identity and scope are captured before awaits, so changes during approval cannot be hidden by mutating a provider object.

`beginNative.bindSession` receives an actual SDK abort closure from both production create/open paths. Source revoke checks the actual current SessionRegistry entry before calling it, cancels pending native work and awaits both SDK and runtime shutdown. An actual SDK transport held during package revoke first reproduced the old missing-abort failure, then passed after this change; reload after the completed drain starts a separate run.

`withUiTransition` revokes only actual window owners (no `isSessionBound` method), drains those callers, and blocks new UI bindings during its action. Native owners retain their own selections, active model run and shared owner. An actual backend/SDK regression executes a native command inside the UI transition, observes the old UI token rejection, rebinds UI and reads the same worker PID. The package source remains enabled in this test; full package disable continues through the full revoke path.

The source descriptor adds `contentHash` and `deliveryProjection: "required"` comparisons. The `requiredSources` interface is defined for the shared installed-source provider. Required-policy selection, conflict/unavailable handling and full knowledge consumer are still pending, so these fields do not yet constitute required publication enforcement.
