# Skill upgrade — 集成与验收记录

日期：2026-09-19。分支：`skill-upgrade`。

## 已落地

- Nature：20 个技能、745 个来源文件。
- Scientific：148 个技能、1,806 个来源文件；另外 18 个特殊/不明确许可条目仍不默认分发。
- Academic：4 个技能、2,737 个普通来源文件，包含完整 Pi wrapper、原始命令与模式资料。四个重复的 `skills/*` 软链接入口按 Windows 可移植性策略省略，使用真实根目录入口。
- 三个来源固定 commit 与归档 SHA-256；ARS 可执行 wrapper、命令模板及相关清单另有固定文件哈希。运行时拒绝关键运行文件重定向或哈希不匹配。
- ARS 本地使用依据是本次用户确认的独立授权，记录为 `separate-permission`。这不是由软件授予的许可，也不推定涵盖重新分发。因此默认发布包仍明确排除 ARS。

## 冲突修复

1. 使用原始、固定版本的 Pi wrapper，经宿主适配层处理命令；不并行启用第二套路由/提示词过滤器。
2. ARS 会话启停、任务选择、恢复和分支切换保持一致；普通闲聊不携带 ARS 兼容说明。
3. `academic-paper-reviewer` 不再误命中 `academic-paper`；连字符与自然语言名称采用精确/最长匹配。
4. 回复审稿与审稿、润色与完整起草分阶段处理，后续任务也会收回旧的强制工作流选择。
5. 多个来源同时被提及时仍只选择一个执行主工作流；明确比较时可作为只读对照资料。
6. 完整论文流程不再回退为每日文献推送。
7. `/ars-full` 按规范目标与原始用户参数路由，不从展开后的阶段说明一次激活全部 ARS 技能。
8. 流式运行中拒绝改变 ARS 工作流/模式，提示等待空闲；不声称当前运行中的系统提示已经重建。
9. 遇到用户同名技能占据 ARS 入口、或 vanilla wrapper 与宿主适配层重复安装时，明确拒绝并说明，不覆盖用户技能。
10. Scientific 文献综述中的强制 AI 绘图要求有明确宿主兼容性覆盖，不构成额外图像、付费 API 或资料外发的授权。已有工具权限、只读模式和证据/发布检查保持有效。

## 使用

重新载入开发版后，可先显式运行：

```text
/ars-pi-doctor
/ars-plan 你的研究问题
/ars-reviewer
/ars-full
```

`/ars-pi-start` 允许后续相关科研任务自动选择 ARS；`/ars-pi-stop` 撤回此模式。普通任务仍按原有规则筛选模型可见的技能。

- 自动发现最多 6 个补充研究技能，摘要估算预算约 6 KB。
- 这不是整个会话的上下文上限：原生 `/skill:*` 展开会读取完整正文。
- Doctor 会执行 Python/import yaml、pandoc/tectonic 等依赖探测命令，但不自动安装依赖。

完整机制、安装、授权开关、更新与回滚说明见 `docs/research-skill-packs.md`。
