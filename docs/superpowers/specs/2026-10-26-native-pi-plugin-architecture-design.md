# 原生 Pi 插件 + Drone UI：主体功能插件化提案

日期：2026-10-26。状态：**已批准；P0–P7 实现中**。

用户确认：卸载全部功能插件后，Drone 仍是可用的通用 Pi 桌面客户端；知识库、研究工作流、任务编排、分析及对应页面均由插件提供。此前四项外部验收保留未完成，MinerU/GROBID、B8/B8-2 继续暂缓，本提案不恢复这些工作。

## 1. 要达到什么结果

交付单位是普通 Pi package：同一 npm tarball 可以直接由官方 Pi 安装并执行领域能力，在 Drone 中额外加载该包声明的桌面 UI。Pi 的包发现、extension API、skills/prompts/themes 和包身份规则是基础；Drone 不要求普通第三方包转换格式。

“等同官方插件”分为三项分别证明：

1. **格式相同**：原生 Pi 读取官方 package.json/pi 或约定目录，无需 Drone 清单、构建器或加载器。
2. **功能可移植**：第一方插件的领域行为、存储与关键闭环不依赖 Electron 或 Drone backend；必要批准通过官方 Pi 支持的交互完成，无交互环境不暗中批准副作用。**2026-10-29 用户修订**：在官方 Pi CLI 中独立使用科研插件不是实际使用场景。本项保留为格式与边界约束（领域实现不依赖 Electron/Drone backend、不 import 宿主），验收降为“官方 Pi 能安装、发现并加载入口、注册声明的工具/技能且不报错”的冒烟；不再要求每个领域功能在原生 Pi 中完成真实闭环，也不为此单独维护第二套完整适配器的行为对等测试。
3. **桌面增强可选**：Drone 的 React 页面、桌面服务入口和权限元数据属于额外声明，不冒充 Pi 官方标准。普通 Pi 不加载桌面入口；没有专属 UI 的官方插件仍能在 Drone 中获得通用工具/结果与支持的交互展示。

官方包说明：[Pi Packages](https://pi.dev/docs/latest/packages)；扩展合同：[Extensions](https://pi.dev/docs/latest/extensions)；交互模式差异：[RPC Extension UI](https://pi.dev/docs/latest/rpc-extension-ui)。已对照本机锁定 SDK 1.1.0 的同名文档。latest 文档不是锁定版本的能力保证，兼容矩阵必须分别运行。

## 2. 当前架构为什么还没有达到目标

设计基于 Drone main `a8f004bf` 与插件 main `d2f76a0`，不以当前聊天原始目录的旧分支作为主线。

| 已观察到的边界 | 实际问题 | 需要改变的归属 |
| --- | --- | --- |
| `plugins.lock.json` 将 knowledge、research、analysis 列为必需插件 | 外置 npm 包仍是宿主构建/启动依赖；删除可选插件的测试不能证明零领域插件宿主 | 改为可选安装；科研发行预设只决定默认安装，不决定宿主能否构建 |
| `backend/src/create-backend.ts` 直接装配知识维护、每日发现、研究写入、分析、领域记忆等服务 | 领域生命周期仍归宿主，迁走算法不等于迁走功能 | 插件拥有领域服务，宿主只发现和管理通用生命周期 |
| `renderer/src/plugins/knowledge-api.ts` 逐项映射知识/Zotero/研究 API，`plugin-api/ui-wire.ts` 集中大量领域 wire 类型 | UI 虽在插件中，后台接口仍按领域在宿主定制 | 领域操作/schema/事件/类型与 UI 一起归插件；宿主只保留有限通用路由 |
| `desktop-ui-pack` 集中完整知识界面，`pi-knowledge` 单独提供能力 | 一项功能分两包安装/版本协调，升级与启停容易不一致 | 优先按领域形成能力+UI 同包，聚合包只组合 |
| `pi-core/src/index.ts` 仍从宿主工作区的 tasks/shared 取构建输入 | 自包含发布产物与独立维护源码是两回事 | 任务领域源码、状态机、工具和 UI 归 core/tasks 插件 |
| `session-engine/sandbox-loader.ts` 发现并代理注册工具 | 只覆盖工具代理，不能推导事件、命令、provider、自定义终端 UI 全兼容 | 列出官方扩展兼容矩阵，改通用运行时适配；不为兼容而静默绕开已有隔离 |

现有迁移与验收仍有效，但其完成范围不等于本提案新增的“零领域插件宿主”。

## 3. 方案比较

| 路线 | 优点 | 不足 | 决策 |
| --- | --- | --- | --- |
| 继续外置包，宿主按领域 `/host` 装配 | 改动小，复用现状 | 仍需改宿主接入功能，零插件无法成立 | 不作为最终方案 |
| **官方 Pi package + 可选 Drone 桌面增强 + 通用宿主机制** | 同一领域实现供 CLI/桌面使用，功能可独立安装/卸载，保留丰富 UI | 需要生命周期、服务路由及领域合同迁移 | **推荐** |
| 仅使用官方 RPC，所有界面只依赖现有工具结果/对话框 | 宿主小、适配少 | 独立知识工作区、未开会话时的查询/任务及完整页面难以表达；终端自定义组件也不会自动成为 React UI | 适合作为基础兼容通道，不作为全部产品架构 |

保持现有 SDK 路径作为迁移起点；不把更换整个会话引擎或升级 Pi 主版本作为先决条件。运行时隔离如何承载完整官方 API，由第一阶段兼容矩阵决定，不能先承诺工具代理就是全兼容。

## 4. 宿主与插件的边界

**宿主保留的机制**：Pi 会话/模型/provider 连接、项目与信任、包安装发现及版本管理、授权与凭据代理、受约束的文件/网络/子进程能力、通用资源预览、事件/请求传输、导航/页面/设置/结果卡挂载、错误诊断。通用工具调用是否允许由宿主机制裁决。

**插件拥有的产品功能**：研究任务计划和验收状态机、任务 UI、Vault 索引与语义查询、知识审阅/维护/每日发现、研究来源与引用/证据门禁、Zotero 和 Protocols.io 领域逻辑、分析流程/科研方法、证据胶囊及各自页面/设置/文案。核心宿主不保留这些功能的备用完整实现。

计算边界：通用进程/SSH 执行和授权属于机制；具体分析流程、参数、结果审核与科研主机页面属于插件。协议连接能力和凭据代理可复用，协议特定的业务操作不能借“适配器”继续留在宿主。

移除功能插件后对应页面和入口消失；基础聊天、项目、模型配置、包管理仍可用。产品仍可默认安装科研套件，让新用户获得科研工作台，但预设包必须可卸载，不能进入宿主的必需运行依赖。

## 5. 包形态与两种 UI

建议每个功能包包含：

```text
pi-knowledge/
  package.json             # 官方 pi.extensions / skills 等声明
  dist/extension.mjs       # 官方 ExtensionAPI 入口
  dist/runtime.mjs         # 领域实现；由入口复用，不单独复制实现
  skills/                  # 官方 skills
  plugin.manifest.json     # 可选 Drone 增强声明；沿用并演进现有清单
  ui/plugin.json           # Drone 页面/面板/设置入口
  ui/dist/index.js         # 已构建桌面 UI；不导入 Pi/Electron
```

不另创 `.droneplugin` 格式，不复制一份与 `pi.extensions` 相矛盾的工具入口清单。现有 Drone 清单中的入口/版本可校验引用官方字段，不维护互相漂移的权威定义。普通 Pi 包可没有 `pi` 字段而使用官方约定目录；发现器须同时覆盖。

第一方同领域能力与 UI 同包。`research-suite` 只做标准 Pi 资源组合和桌面安装预设；若单包与 suite 同时安装，按同一来源/包身份去重，不产生两套工具、UI 或写者。`desktop-ui-pack@0.2.0` 保持已发布不可变；功能移走后用明确的后继版本/迁移记录退役其旧贡献，禁止长期双注册。

Pi 原生的 confirm/input/select/notify 等交互由 Drone 适配为桌面组件。`ctx.ui.custom()` 的终端组件不自动转成 React 页面；能力声明要区分通用交互、终端专用 UI 和 Drone 专属页面。只有实际测过的 API/版本/模式才能标记兼容。

兼容性要分开记录：包被发现、扩展被加载、工具/命令/事件/provider 行为、UI 模式和安全策略。应优先复用真实 Pi loader/运行时，避免不断扩大手写的 ExtensionAPI mock；任何隔离架构调整都必须先证明不会降低当前批准与权限边界。

Pi runtime 只由宿主提供，不打入插件。官方文档对 host-provided peer 的建议与当前第一方 `>=1.1.0 <2.0.0` 声明存在差别，第一阶段按锁定 SDK/最新 SDK 实测后统一策略；不能机械调整声明就宣称兼容。

## 6. 领域后台和 UI 如何连接

逻辑路径：`插件 UI → preload 通用桥 → 插件运行时的声明操作 → 领域实现`。模型路径：`官方 Pi extension/tool → 同一领域实现`。宿主不再新增 `getKnowledgeX`、`getResearchY` 这类具名 IPC。

通用桥仅暴露包已注册的操作与事件，每项包含请求/结果 schema、作用域、是否产生副作用和所需批准。UI 的调用身份、session/workspace 绑定由宿主注入；不能由 renderer 自报插件名冒用其他包权限。UI 查询不制造模型工具回执，模型阅读回执仍绑定真实会话与调用链。

在没有模型会话时，知识浏览等功能仍需运行：允许插件在 Drone 增强声明中提供可选的桌面激活工厂，由通用 loader 发现。这是明确的 Drone 增强，不能成为 native Pi 运行的条件。工厂只连接平台端口并启动本包 runtime，不承担第二份领域实现。

在 Desktop 内，工具适配与 UI 服务复用对应作用域的同一 runtime；原生 Pi 入口自己创建相同实现。应用级资源、workspace/Vault 数据和 session 证据分别管理，禁止 process 全局账本或 `Symbol.for` 桥。一个会话关闭不得清除另一个会话状态。

新通用 `plugin-api` 只包含生命周期/传输/授权/挂载等机制；知识、任务、研究模型与 wire schema 移回对应插件。领域能力依赖由带版本的 service contract 声明，宿主只路由和协商，不实现领域服务。公共能力名由提供者命名，不继续把全部科研领域硬塞入宿主固定枚举。

不把 npm 的普通库依赖一律禁止；禁止跨插件导入实现、依赖共享模块单例或直接访问对方数据。套件组合遵循官方嵌套资源规则。现有“插件只能向宿主要领域能力”的规范需明确修改为“向能力提供者请求，宿主只管理边界”。

## 7. 生命周期、数据与安全

安装包版本是一致单位；UI 可以隐藏，但隐藏 UI 不停工具。停用整个插件则停止新调用、卸载贡献，并在安全边界结束/取消在途工作；中途外部写入必须先记录待对账状态，不允许以 kill 替代清理回读。

后台任务的业务决策和状态归插件；宿主可提供通用调度/唤醒机制，原生 Pi 侧需明确进程存活条件，不承诺 CLI 退出后仍自动维护。

同一插件新旧版本不能同时写同一数据集。复用现有 Vault 路径和持久化格式，列出每类数据的所有者、写者与 schema 版本；原子写不等于多进程互斥，CLI/Desktop 同时运行必须有实际可验证的协调或明确拒绝第二写者。卸载默认保留用户数据；数据删除是独立授权。

升级先验证候选版本和数据兼容，再切换贡献；失败恢复旧运行版本。代码回滚与数据回滚分开：不可逆 schema 升级不得宣称可直接降级，需在该迁移 PR 明确备份与恢复流程。

保持现有信任与权限门禁。普通官方插件的未知权限不得默认为安全；对无法支持的 API/隔离模式给出明确诊断。Node 独立进程不是 OS 级恶意代码沙箱。现有共享 React UI 必须作为已信任代码管理；本阶段不顺带承诺 iframe/独立 origin 隔离，未来若要运行不可信 UI，应另开设计。

## 8. 实施顺序与每一步的删除标准

这些是依赖顺序明确的工作包，不要求一次提交覆盖整个阶段。每个领域迁移都要先跑通“安装 → 使用 → 停用 → 卸载 → 恢复”，再扩展到下一个。

| 顺序 | 工作包 | 具体交付 | 通过与删除标准 |
| --- | --- | --- | --- |
| P0 | 边界清单和原生兼容基线 | 罗列宿主领域服务、IPC、类型、UI、构建输入、插件持久化及当前 Pi patch；建立普通官方包/增强包的版本和 API 矩阵 | 有真实空宿主与原生 Pi 基线；每项迁移有明确归属，失败如实记录；此阶段不谎称空宿主已实现 |
| P1 | 通用生命周期/服务/页面通道 | 复用包身份与信任；增加最小声明式操作/事件桥、动态导航和可选激活工厂；实现官方基础交互适配 | 第三方示例包无需修改宿主即可提供操作+UI；无模型会话可打开只读页面；会话隔离/停用/取消验证通过 |
| P2 | 知识完整垂直迁移 | 将知识后台装配、维护/发现、领域 schema、完整 UI 合并进知识功能包；连接器依赖通过合同调用 | 删除宿主知识业务装配和具名 IPC、knowledge-api 映射；同一 tarball 原生 Pi/Drone 实际闭环，移除插件不影响基础宿主 |
| P3 | 研究与连接器完整迁移 | 研究服务、来源策略、Zotero 领域逻辑和研究 UI 移入所属包；凭据存储只经通用代理 | 删除宿主 research/Zotero 业务实现与必需依赖；保留原读取证据与批准语义。外部账户四项仍不自动执行或改 PASS |
| P4 | 任务与领域记忆迁移 | pi-core/tasks 源码独立，任务状态机、task UI、产物验收规则和领域记忆归插件 | 删除宿主 @drone/tasks 运行依赖和内置领域任务状态机；无任务插件仍可进行普通 Pi 对话/工具调用 |
| P5 | 分析与科研证据迁移 | 分析控制器、方法 registry、结果审查、证据 capsule 与科研页面归对应包 | 删除宿主领域 adapter 装配/分析业务；通用执行/授权机制保留，具体流程由插件声明 |
| P6 | 发行、安装与旧通道清理 | 首方同包 UI 完成；suite 只组合；默认科研预设可卸载；清除旧 UI 集中包贡献、生成领域 shim 与领域锁依赖 | 零领域插件可独立构建/启动/聊天；官方普通包无需 Drone 清单；无源工作区依赖；卸载/升级/回滚真实验收 |
| P7 | 正式包矩阵与最终审计 | locked/latest 原生 Pi、正式 macOS 安装包、同 tarball 双端验证；记录版本、权限、数据与生命周期证据 | 逐项检查删除清单、源依赖、安装包资源和真实会话；未测平台保持未完成，不以静态扫描代替端到端结果 |

依赖主线：P0 → P1 → P2 → P3/P4 → P5 → P6 → P7。P2 先验证整套模式，避免同时改六个领域；P3/P4 只有在公共接口稳定且数据归属不冲突后才能并行。分析的任务/知识依赖必须显式提供，不得使其悄悄重新成为宿主功能。

迁移期间的旧入口逐项记录确切适用版本和删除条件；同一领域迁移完成就删除旧路径，不保留无期限“兼容备用实现”。已发布 1.x 公共合同不得直接破坏；有破坏性删除时提供并行的新合同版本和明确迁移窗口，待消费者完成升级后清理，不能把新接口伪装成原 1.x 的兼容变更。

## 9. 最终验收：证明是插件，而非换目录

- Drone 源码/依赖树/安装包中无功能插件的必需实现；不下载科研插件也可构建和启动通用宿主。
- 官方格式包可被未修改的 Pi（锁定版与 latest）安装、发现并加载，注册清单声明的工具/技能；不依赖 Drone 工作区、私有生成物或 host-only 服务（2026-10-29 修订：不再要求原生 Pi 关键闭环）。
- 同一包在 Drone 安装后自动提供工具、服务、页面与设置；加入新功能包不改宿主源码或宿主领域类型。
- UI 触发和模型触发使用同一领域规则/存储，权限一致，回执分别保持真实调用身份。
- 删除任一可选提供者后宿主正常；依赖方明确不可用，不伪造成功，也不启用宿主备用领域实现。
- 会话结束、插件停用、升级和失败后无遗留监听/worker/重复工具/双写；用户数据可回读。
- 无研究包的基础宿主、独立知识包、完整套件、普通第三方 Pi 包、损坏/不兼容包均有真实安装或会话证据。

2026-10-26 用户批准设置目标并行实现。执行记录见 [P0–P7 计划](../../pluginization/native-plugin-implementation-plan.md)。新包发布须有对应版本和验收证据；旧四项外部验收不纳入本目标，暂缓功能不恢复。
