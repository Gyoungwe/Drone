# Drone 客户端 UI 全面整改调查与实施计划

**状态：** 已按 v0.32.0 发布代码复核，P0/P1 范围已冻结；本分支已落地 P0/P1 的行为改动并完成桌面类型检查与针对性测试
**日期：** 2026-10-14
**基线：** `v0.32.0` / `022d0eac1d585ed295e09deb22b18de2ed13ef16`
**范围：** Electron 桌面端 renderer、设置、工作台、右侧上下文面板、Composer、文件预览、知识工作台、LAN Web 观察入口与共享 UI 控件
**优先级：** 研究任务效率、视觉品质与品牌感、复杂状态与可靠性三者同等优先

## 1. 目标与边界

这次工作建立一套可持续的 UI 基线，解决高频路径上的理解、反馈和窄窗口可靠性问题。调查要回答：

1. 用户能否在几秒内理解当前工作区、运行状态和下一步动作。
2. 聊天、任务、变更、文件、过程细节和设置之间是否存在重复或过深层级。
3. 视觉 token、组件反馈、动效、响应式和无障碍是否形成一致规则。
4. 长任务、权限等待、错误、空态、长文本和窄窗口下，界面是否仍然可靠。

本轮实施只处理已验证的 P0/P1，不做一次性换皮；新增 IPC、Pi SDK 依赖、持久化和插件宿主改动均不在本轮范围内。

## 2. v0.32.0 复核结论

### 已经完成、从本计划中移除的旧问题

- 右栏页签已经从“任务 / 过程 / 产物”收敛为 `任务 / 变更 / 文件 / 主机`；文件变更优先展示，运行过程进入“变更”内的默认折叠细节。
- 设置页已经按“身份 / 能力 / 资源 / 通用”分组，并保留高级能力分区；原先“所有分类平铺”的问题不再作为 P0。
- 右栏滚动区已统一 `scroll-fade`，不再重复整改单个列表的边缘渐隐。
- 交付卡、首页主线卡、消息淡入、页脚数字和 reduced-motion 已有 v0.32.0 基线，后续只检查一致性和回归。
- 知识图谱快照已做响应式优化，本轮不重新设计图谱布局。

### 仍然成立的证据和源码风险

- 静态预览 `ui-preview/compact-workbench-preview.png` 与既有实机记录显示，窄窗口下设置弹窗和右栏仍需验证最小宽度、长路径和多语言文案；源码中的弹窗宽度仍是 `min(900px, 94vw)`，导航宽度在样式层被扩展到 208px。
- `ContextPanel` 当前用 `width 0.42s` 加内容 `0.38s` 位移动画，超过高频工作台面板应有的即时反馈预算；面板内容和页签按钮也缺少明确的键盘方向键行为与 `aria-controls` 关联。
- `Button` 的按下反馈仍是 `translateY(1px)`；`Switch` 使用 `transition-all`；`Dropdown` 菜单即时挂载；`Tooltip` 只有 opacity、固定居中锚点和重复 300ms 延迟。这些都是统一反馈的 P0。
- `ProcessTab` 已隐藏运行细节，但任务、变更、文件和交付卡仍需要明确“摘要 / 权威来源 / 跳转”的层级，避免同一状态在消息流、任务卡和右栏重复解释。
- 通用控件已有 focus ring 和 reduced-motion 基线，但需要为 tabs、dialog、switch、tooltip、折叠细节补齐可验证的 ARIA 关系和焦点回收。

## 3. 设计方向

采用“设计系统规则先行，再用垂直切片验证”的方案：

1. 固定状态、密度、动效、响应式和焦点规则。
2. 先修复设置 / 右栏 / 共享控件这些高复用面。
3. 用三条路径验收：新建会话并完成交付；长任务遇到权限并打开文件；设置模型或外观后回到原会话。

这比一次性重做更容易定位回归，也比只改聊天更能保证工作台、设置和复杂状态使用同一套规则。

## 4. 调查与验证工作流

### 阶段 0：基线冻结

- 固定 commit、远程分支、主题、语言、缩放和窗口尺寸。
- 在 375、768、1024、1440 以及实机尺寸采集设置、右栏、Composer、文件预览截图。
- 区分静态预览、LAN Web 和 Electron 实机证据；每个问题记录来源与复现路径。

### 阶段 1：界面地图与状态权威

盘点会话标签、消息流、Composer、任务、变更、文件、主机、过程细节、产物卡、文件阅读器、设置分类、知识库、子智能体和权限 / 错误 / 空态 / 取消态。

每个区域记录入口、必须信息、可隐藏信息、权威状态来源、返回路径、键盘路径以及空 / 错 / 满状态。重点检查：

- 同一事实是否在消息流、任务清单和右栏重复呈现。
- `任务`、`变更`、`文件`、`过程细节` 是否都提供清晰的摘要与跳转，而不是复制整块内容。
- 文件预览是否能回到原会话和原轮次，错误是否保留可恢复操作。

### 阶段 2：设计系统与动效审计

保留中性浅色、科研工作台气质，不引入装饰性风格。统一检查颜色语义、字体层级、4px 间距、圆角 / 阴影、图标尺寸、状态色和长文案换行。

动效遵循 Emil 设计工程规则：高频操作优先即时反馈；进入用 ease-out，移动用 ease-in-out；UI 动画通常小于 300ms；只动画 transform / opacity / 颜色；交互控件必须有 active 与 focus-visible；`prefers-reduced-motion` 下停止连续装饰动画。

建议 token：

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
```

### 阶段 3：响应式窗口契约

| 窗口宽度 | 目标布局 |
| --- | --- |
| ≥1440 | 导航、主工作区、右栏并排 |
| 1024–1439 | 右栏限制在约 320px，长标题和路径可断行 |
| 768–1023 | 右栏变为覆盖式抽屉或受限列，不挤压 Composer |
| ≤767 | 单列工作区，设置与右栏改为可滚动的全宽面板 |

每档都检查中英文、200% 缩放、深色主题、长会话标题、长路径、长模型名、超长表格与大量任务。

### 阶段 4：极端数据与状态压力

使用 Demo / Worst case / Empty / One / 1000 rows 夹具覆盖长文本、0 / 1 / 999+ 任务、空项目、错误、重试、取消、超时、权限等待、预览失败、多语言混排和 emoji。按 Broken / Ugly / Fragile 记录，先修复会阻断任务的 Broken。

### 阶段 5：可访问性、性能与架构

- 键盘完成打开面板、切换 tabs、展开细节、确认操作和关闭 dialog。
- Dialog、Tabs、Switch、Tooltip、折叠细节和状态点具备正确 ARIA 关系。
- 所有可操作元素有稳定 `focus-visible`，颜色不作为唯一状态信号。
- 超过 100 项的列表有虚拟化、分页或明确限制；检查高频 Zustand selector 是否返回稳定引用。
- 不新增 renderer / Pi、跨包、IPC、i18n 或插件宿主违规。

## 5. 修订后的实施范围

### P0：本轮必须完成

1. **窄屏与滚动可靠性**：设置弹窗使用可收缩的导航 / 内容两列，内容最小宽度为 0；小窗口允许全宽纵向滚动，禁止非预期横向滚动；长路径和长模型名可断行或省略。
2. **右栏层级和语义**：保留 v0.32.0 的 `任务 / 变更 / 文件 / 主机` 命名；为 tab 补齐 `aria-controls` / `tabpanel` 关系；让变更与运行细节明确为摘要与二级明细，避免复制整块任务状态。
3. **高频控件反馈**：Button / IconButton / Switch 增加 100–160ms 的按下反馈；Switch 只过渡颜色和 thumb transform；Dropdown 采用 150–200ms、从触发器方向出现的 transform + opacity；Tooltip 保持首次延迟但支持邻近 tooltip 快速切换。
4. **面板速度**：右栏打开 / 关闭控制在约 220–280ms，使用 drawer curve；内容只做短距离 transform + opacity，避免 0.42s 宽度动画拖慢响应。
5. **焦点与状态**：补齐 tab 键盘语义、折叠细节焦点可见性、设置 dialog 的初始焦点 / Escape 回收；运行中、等待确认、完成、失败在右栏和消息流使用一致语义。

### P1：紧接着本轮完成

1. **Composer 和选择器契约**：核对模型 / 思考档 / 权限 pill 在窄窗口、长模型名和键盘操作下的布局与关闭行为。
2. **文件预览路径**：从文件卡打开预览后保留来源轮次 / 返回入口；空、加载、失败、取消态提供一个明确的下一步。
3. **长内容策略**：任务标题、文件路径、技术字段、错误详情统一使用 `min-width: 0`、断行 / 截断和可复制完整值。
4. **列表性能与状态**：任务、变更和运行细节在 100+ 项时采用明确的限制或虚拟化；避免折叠细节打开时重复订阅整条消息流。
5. **三条垂直路径验收**：新建并完成任务；权限等待后打开文件；设置模型 / 外观后回到原会话，并在 375 / 768 / 1024 / 1440 采集证据。

### P2：后续批次

- 设计 token、图标、圆角、阴影和密度全面收敛。
- 知识图谱、子智能体、高级设置和启动 / 完成反馈的细节抛光。
- 完成 Worst-case / Empty / One / 1000 rows 的可重复开发夹具与覆盖矩阵。

## 6. 验收指标

- 四个关键宽度没有非预期横向滚动。
- 所有关键控件有 hover、active、focus-visible、disabled 状态。
- 关键路径可以完全通过键盘完成，tab 切换与折叠内容有正确读屏语义。
- 每个任务状态只有一个权威展示位置，其他区域只给摘要或跳转。
- 重要操作的首个视觉反馈不超过 160ms；普通 UI 动画不超过 300ms。
- reduced-motion 下不保留连续装饰动画。
- 极端数据没有 Broken 级问题；100+ 列表有性能策略。
- 中英文长文案、深色主题和 200% 缩放通过检查。
- 不新增 renderer / Pi、IPC、i18n、插件宿主和跨包违规。

## 7. 交付物与实施护栏

后续批次应保留 UI surface inventory、状态权威图、设计 token / 组件审计、动效审计、响应式 / 无障碍矩阵、Worst-case 报告和 P0/P1/P2 backlog。修改代码前重新读 `docs/INDEX.md`，完成后检查索引是否准确。

本文件更新后先提交文档与索引，再提交 P0/P1 行为改动；本次只创建分支和 PR，等待统一审阅，不合并、不发布。
