# 知识整页插件化与原生 suite 收口设计

## 已知基线

发布证据分支的 main 合并与门禁独立进行。本设计基于 Drone e5ec4f01，公开包为 pi-core 0.1.8、pi-knowledge 0.2.1、pi-research 0.2.0、research-suite 0.1.10。未合并的 scientific-agent-upgrade 不包含在内。

`knowledge.page` 已支持整页贡献、停用及故障回退。当前 KnowledgeView 与 46 个知识组件/测试文件仍由宿主维护，约 80 处 getPi 调用不能直接复制到外部插件；插件只允许使用公开 DroneUI API。

原生 suite 的真实会话已复现：全部扩展加载、task_plan 批准、两源阅读、回答、候选笔记写入成功；task_reconcile 将文件验收标为 blocked / file-unavailable。公开 core 发送 drone:task-read-check，但读取权限处理器目前只在 Desktop backend 注册。任务完成断言应保持失败直到修复，不能以工具 exit 0 替代。

## 方案比较

1. **推荐：整页归插件，宿主保留轻量默认页。** 页面组合、总览/网络/审阅/设置、笔记阅读及文案由 desktop-ui-pack 拥有；宿主保留导航、上下文、授权、数据服务和加载边界。无插件/停用/故障时仍显示知识绑定状态、打开已绑定文件夹及插件管理入口。高级知识页面仅在插件启用时提供。不会复制一份完整页面回宿主。
2. **完整内置页保留，同时提供另一整页插件。** 关闭插件后所有原功能保留，但宿主仍拥有知识产品 UI，只能称整页扩展完成，不能称完整所有权迁移。
3. **分阶段迁移页面。** 先总览/阅读，再网络/审阅/设置；每步易验证，但期间继续保持 PARTIAL，不能以首批迁移宣布整页完成。

## 推荐方案的实现边界

- 在 drone-plugins/desktop-ui-pack 中维护知识页源码、文案、样式及组件回归，使用 knowledge.page；保留其他插件 knowledge.tab 贡献发现和渲染能力。
- 从现有调用提取明确的公开 Knowledge UI 端口：概览、搜索/列表、阅读、图谱、审阅、绑定/维护及状态订阅。只暴露所需方法，不把 window.pi 或整个 backend 对象交给插件。
- 宿主通过现有 preload/IPC 实现端口；同步 DroneUiApi、host-api.manifest、生成的声明与 shim、UI SPEC 和插件公共合同。renderer 不 import backend/Pi，不跨仓库引用源码。
- 保留稳定的 cwd/session/binding revision 上下文、事件订阅清理和异步结果过期保护；插件切换或会话切换不能显示上一个 Vault 的数据。
- 原有写操作继续经过宿主批准，文件路径仍受 Vault/工作区约束；插件不能因为获得 UI 端口而获得额外写权限。
- 迁移时保留 Git 历史；迁移与行为调整分开提交。删除迁移后已无用途的宿主页面实现，不保留第二套完整产品 UI。
- 插件异常由现有 PluginEntryHost 错误边界展示默认页，并保留诊断；恢复插件能回到当前上下文。
- 发布候选更新版本和 manifest。任何新 npm 版本另按发布流程取得明确版本授权后发布，不覆盖本次已公开包。

## suite 原生任务完成修复

为 native Pi 提供按会话绑定的读取权限处理器，走现有原生 UI 授权接口；只处理自己的 cwd/session 请求，拒绝或缺 UI 时不放行。Desktop 继续使用现有权限引擎，不重复注册 native 处理器。不得直接放行事件、改 journal 状态或关闭 task workbench。

使用三个实际打包扩展和真实 SDK 会话覆盖：无批准阻断、任务批准、两源读取、证据不足拒绝、候选笔记写后回读、文件验收 completed；另验证读取授权拒绝、跨会话隔离和无 UI 情况。离线脚本模型只验证执行和回执，不声称科学审核通过。
