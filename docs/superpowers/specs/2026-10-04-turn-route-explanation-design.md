# 每轮路由解释：整合现有过程面板

日期：2026-10-04

状态：供评审的设计与实施计划；尚未修改产品代码。

用户已明确的目标：理解每轮为什么这样走。本文以“聊天摘要 + 现有过程面板详情”为建议方案，不增加路由页签。

## 1. 现状和设计依据

基线为 `docs/architecture-v2` 的 `9a54653`。参考 Archify HTML 解释的是 `2b15c40` 的路由机制，包含“对话 / 技能路由 / 宿主任务门”和两个示例分支；它的地图、节点搜索、导出等属于架构阅读器功能。

现有实现已经有 `drone-turn-route` 记录，`TurnRouteCard` 在聊天内用折叠文本展示。`ProcessPane` 已按轮展示运行记录，`TurnFooter` 已通过 `focusProcessTurn(turnIndex)` 打开对应轮次。右栏固定宽度 372px，已有任务、过程、变更、产物、子智能体、计算六个页签。

当前缺口：过程面板没有消费 route；聊天路线缺少清晰视觉结构；路由和运行记录缺少可靠的持久化轮次关联。现有记录主要是回复开始前的快照，不能当作整轮执行轨迹。

## 2. 信息归属与去重

| 位置 | 回答的问题 | 展示内容与边界 |
| --- | --- | --- |
| 聊天路由摘要 | 这一轮为什么这么处理？ | 一行结果及“为什么”入口，窄屏允许两行。不重复列工具、用量、待办、产物或多段路由解释。 |
| 聊天过程块 | 现在在做什么？ | 沿用已有即时进展和工具折叠，不再增加第二个路由过程块。 |
| 过程面板对应轮次 | 为什么选这条路，后来发生了什么？ | 上方“本轮选择”，下方复用“运行记录”。路径图和选择依据只在此处详述。 |
| 任务面板 | 整项任务完成到哪？ | 任务契约、清单、里程碑、当前待办；不复制每轮路由图。 |
| 聊天决定卡 | 现在需要我决定什么？ | 复用已有审阅、继续、结束入口；路线图只提供跳转，不增加一套操作按钮。 |
| 输入框上方授权区 | 哪项操作需要授权？ | 沿用 ApprovalDock；路径解释不批准操作。 |
| 变更 / 产物 / 子智能体 / 计算 | 各自的详细结果和控制 | 保留现有职责。路径节点只链接相关对象，不复制列表和控制区。 |

“摘要 + 同一事实的详情”是有意的渐进展示；同一列表或同一操作在两个地方完整出现才是要消除的重复。本轮不重构既有 RunInspector 内的所有跨面板摘要。

## 3. 聊天与面板布局

替换现有 TurnRouteCard 的折叠段落为轻量摘要。保留其位于用户消息之后、助手回答之前的位置，不与阶段进展混合。示例：

- 新检索：`本轮选择：文献发现 · nature-academic-search　为什么 ›`
- 接续任务：`本轮选择：沿用任务检查点　为什么 ›`
- 状态询问：`本轮选择：查看当前进度　为什么 ›`
- 只读复用：`本轮选择：复用已有文献　为什么 ›`
- 普通对话：`本轮选择：直接回答　为什么 ›`

摘要描述入轮选择，不随工具执行成功而改成绿色“已完成”，也不复述实时阻塞原因。真正的运行状态继续由现有过程块、状态行和决定卡承载。

过程面板保持最新轮在上的列表结构。每轮内部依次为：

1. 现有轮次标题、用户消息摘要及用量概览。
2. **本轮选择**：路径图及节点选择依据。
3. **运行记录**：复用当前模型、阶段、工具、读取来源与诊断区域。

不在面板顶端再增加一份重复的“全局当前路由”。历史轮次的选择区默认折叠；从聊天点击后只展开目标轮的选择区。点击轮末工具数量则展开目标轮的运行记录。两个入口共享同一轮次定位机制。

手动查看历史轮时，新消息不会把焦点抢回最新轮。路由到达不自动切换页签。用户主动打开的详情在本轮结束时保持可见，直到关闭或切换；不改写原有空闲开关偏好。键盘和屏幕阅读器可使用摘要、节点及返回入口。

## 4. 路径图如何继承参考 HTML

沿用参考图的语义，改为适合 372px 面板的纵向节点和连线。节点表达路由决定，连线表达其依据关系，不作为完成进度条。

### 新检索分支

`这句话：新话题 → 能力：科研 → 阶段：文献发现 → 主技能：nature-academic-search → 回答方式：应用该工作流`

默认显示上述节点的短标签。点击主技能节点，在节点下方展开一到三条依据，例如“识别到文献检索主题”“采用该阶段首个可用候选”。完整技能标识允许换行。

“候选第一项”只在入轮记录包含相应选择原因时显示。现有快照没有完整候选列表；第一版不根据当前安装情况重建过去的候选排序。学术模式等说明来自该轮记录。

### 接续与任务门分支

`这句话：接续 → 沿用任务检查点 → 入轮任务门：等待审阅 / 阶段限制 / 可继续`

继承的技能明确标为“沿用”；没有证据时不画成重新选择，也不补填旧技能。任务门仅在该轮有记录时显示，普通回答不必经过一个假想的任务门节点。

任务门解释标注“回复开始时”。若随后解除限制或完成审阅，在运行记录或最新决定卡显示实际结果，并给出“查看当前待办”或“定位决定卡”的链接；保留原快照，避免把当时情况改写成现在情况。

### 状态和视觉规则

蓝色表示已选择或已沿用，琥珀色表示记录到的限制，灰色表示未记录；同时提供文字标签，不仅靠颜色区分。路线采用静态连接，不使用持续流动动画暗示执行。无相关分支不显示，无数据不推测。

本轮只交付每轮解释图。全系统地图、语义透镜、导出动画、手动改路由、候选评分面板留待独立需求，不嵌入整套 Archify 页面或第三方 HTML 脚本。

## 5. 数据与组件设计

### 事实来源

继续使用后端路由选择和任务记录作为事实来源；前端只做确定性投影。解释属于可公开的规则和结果，不额外调用模型生成原因，不读取隐藏思考，不从助手正文猜路径。

维持三类独立事实：

- 路由快照：在当时选择或沿用了什么，以及选择依据。
- 运行记录：工具、阶段和宿主事件实际发生了什么。
- 当前任务视图：现在的完成状态、待办和操作资格。

选择某技能不等于执行技能，模型可见不等于调用成功，放下审阅不等于交付验收完成。最终提示构建完成后才能记录“已应用工作流”；只有选择数据时用“已选择”，避免提前宣称提示已写入。

### 轮次关联

给路由信封增加版本、稳定 `turnKey`、记录时间，以及可用的任务/审阅关联 ID；保留 `reportId` 作为事件去重标识。`turnKey` 由宿主在接受输入时分配并持久化，实时用户消息、路由快照和历史映射引用同一个值。不得用提示词哈希充当轮次身份，连续两条相同的“继续”仍是两轮。

沿用会话事件及历史记录通路，不增加独立路由数据库。模型重试属于原轮，重发或分叉的新输入获得新键；页面定位带会话范围，不能跨会话错指。新记录存在明确的选择来源（新选择 / 沿用 / 未选中），实际应用状态与选择状态分开。

旧 route 仍可解析。仅在完整、未截断的会话分支中，允许通过其持久化顺序关联到最近的用户边界，并标记为旧记录关联；截断、缺失或歧义时显示“无法定位原轮”，不关联到猜测目标。无 route 的历史显示“这一轮未记录路由”，不使用当前技能配置补造历史。

### 组件职责

| 改动点 | 计划职责 |
| --- | --- |
| backend 路由扩展和宿主输入适配 | 采集事实、产生稳定轮次关联、区分入轮快照与后续执行。SDK 运行时接入遵守现有 session-engine 边界。 |
| shared `turn-route.ts` 及独立展示投影 | 版本兼容、结构校验、中文/英文解释、节点和边模型。复用已有文本解释作为降级展示。 |
| shared transcript 映射、reducer、轮次投影 | 实时/历史一致；按稳定键去重和绑定。保留旧 turnIndex 的兼容映射，不全量重写其他统计。 |
| `TurnRouteCard` | 替换为只含摘要和定位按钮的聊天组件。 |
| `ProcessPane` / 新增局部路线视图 | 同一轮卡片内展示“本轮选择”和现有 RunInspector。静态小图用原生组件和 CSS/SVG，不引入通用图编辑器。 |
| UI store 的 processFocus | 扩充为会话 + 稳定轮次 + 目标区段（选择 / 运行记录），保留原工具入口。聚焦精确到区段，取消“找到第一个 details 就打开”的隐式行为。 |
| i18n 与 LAN | 文案中英文同步。LAN 使用同一事实和解释投影，以本地折叠详情替代桌面侧栏，保持既有授权边界。 |

若稳定关联需要扩展通信类型，按仓库约定同步 shared、backend、main、preload，renderer 不直接访问 SDK。展示排序、动画和展开状态属于 UI，不写回任务记录。

## 6. 边界与失败处理

| 情形 | 设计行为 |
| --- | --- |
| 没有路由数据或解码失败 | 聊天正文照常显示；过程详情区显示“未记录”或“说明暂不可用”，不伪造默认路径。 |
| 路由晚于回答到达 | 按稳定轮次键补到原轮，不加第二份卡片，不强制跳转滚动位置。 |
| 没有工具调用 | 仍可显示路由解释；零工具不影响过程轮次存在。 |
| 模型失败、取消或重试 | 保留最初选择的事实；失败和重试由现有运行记录表示，不把整条路线标成功。 |
| 运行中补充或排队消息 | 排队期间不声称路由已选；被宿主实际接收并路由时才记录。仅注入同一运行的补充消息标注“补充当前运行”，不捏造一次新选择。 |
| 宿主直接处理任务指令 | 不伪造模型/工作流执行；通过宿主处理结果标注“任务指令”，缺少记录时使用明确缺失态。 |
| 分叉、切会话、重启 | 跳转目标限当前会话分支；已不存在的目标提示不可定位，不跳到同序号另一轮。 |
| 当前任务状态不同于入轮状态 | 各自显示记录时间/性质；只提供当前任务链接，不修改历史快照。 |
| 窄栏、长技能名、大字体 | 文本换行，路径纵排；不压缩成无法阅读的缩略图，无横向滚动要求。 |

## 7. 实施顺序与交付

1. **打通轮次与事实。** 增加带版本的路由信封和稳定关联，统一实时及历史映射，补齐所选/沿用/已应用的区别。先用隔离事件回放证明相同输入、重试和分叉不会串轮。
2. **整合两个展示入口。** 将聊天折叠卡替换为摘要；在对应 ProcessPane 轮卡上方增加路径图；扩展 processFocus 的区段定位，复用现有 RunInspector 和 TurnFooter。
3. **收紧交互与兼容。** 加入缺失态、旧记录降级、任务/决定卡链接、中英文和键盘支持；保留用户查看历史的焦点；LAN 用同一投影提供折叠详情。去掉聊天旧版多段路由正文，不另起路由页签。
4. **验证并打包。** 完成有行为意义的单元、回放、集成及 Electron 界面测试，通过仓库检查后重新构建安装包，验证安装包内实际呈现。截图明确区分设计示意与运行证据。

每一步保持可审阅；这一设计阶段只产出文档和示意图，不修改产品行为。尚未排期，不把工期估计作为交付承诺。

## 8. 验收标准

- 六个右侧页签保持原集合，只有一个完整的路由详情位置；每轮聊天至多一条路由摘要，旧多段文本不再重复。
- 点“为什么”能定位并展开正确轮的选择区；点工具数量能定位同轮的运行记录。相同输入、历史回放、重启、分叉和切会话不会串轮。
- 普通对话、新检索、显式技能、学术模式、只读复用、继续、进度询问、待审阅、阶段限制和解除限制均有符合实际记录的解释。
- 选中技能不显示为执行完成；“继续”不误标人工验收；入轮任务门与后续执行状态可以不同且有清楚标注。
- 异常数据、旧记录、无工具回复、取消、模型失败、事件重复和延迟到达不影响正文显示、不重复卡片、不猜测历史。
- 372px 面板、窄窗口、长技能标识、中英文、键盘访问和减少动态效果设置均可用。
- 先跑相关测试及隔离 SDK/事件回放，再执行 lint、typecheck、test、build、check:arch 的仓库完成检查。修复或明确记录既有失败；不以单个组件测试替代真实数据流和安装包冒烟。
- 提交产品改动时同步 `docs/INDEX.md` 的相关组件职责。本设计稿不把待实现组件登记为已经存在。
