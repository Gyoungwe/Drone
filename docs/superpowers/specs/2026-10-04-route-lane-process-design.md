# 路由位置与泳道过程视图设计

## 背景与目标

Drone 当前的「过程」页按轮次显示倒序卡片，能够展示模型、工具、来源和诊断，但不能稳定表达一轮过程中的位置关系：用户输入如何落到节点选择，工作如何改写「正在做」，任务门与宿主门何时岔出，以及知识沉淀和本轮引用为什么不能连成一条线。

本次升级把正式客户端的「过程」页替换为六条泳道的位置视图，并保留节点内的工具、来源和诊断明细。`/Users/gaoyangwei/test.html` 继续作为独立草图，但与正式客户端使用同一套事件语义和八步样例。`outputs/route-lane-sketch.md` 记录理念、位置规则和草图验收标准；`outputs/drone-base-data.md` 仍是代码、harness 和功能清单，不承担运行时状态。

目标是让实时显示和历史回放得到同一份可重放状态，同时避免过程视图形成第二本账。现有会话 transcript、`drone-turn-route`、任务视图、公开工具结果和研究回执仍是事实来源；泳道状态是纯展示投影，不新增授权、证据或任务持久化语义。

## 核心决策

### 共享、可重放的归约器

在 `@drone/shared` 增加纯函数模块 `packages/shared/src/process-lanes.ts`。模块定义公开的过程事件、六泳道状态、节点状态和边类型，并提供确定性的 `reduceProcessEvent` / `deriveProcessLaneState`。它只消费可观察数据，不读取思维文本，不从 Markdown 链接推断文献已读，也不执行文件、研究或任务副作用。

正式客户端和草图使用同一事件语义：客户端从 `UIMessage` 及其公开字段提取事件；草图使用八步固定事件夹具。草图可以保留独立 HTML，但夹具的字段命名、状态值、原因码和边类型必须与共享类型保持一致。

### 正式客户端的展示边界

`ProcessPane` 不再以倒序轮次卡片作为主布局，而是渲染六泳道位置视图。工具、来源、模型和诊断明细仍可从对应节点展开，继续使用现有公开的 `RunInspector` 数据；它们不再在顶层重复占用一张过程卡。旧会话缺少某类事件时，泳道保留灰色空状态，不补造回执。

### 六条固定泳道

1. **入口**：用户输入、节点选择。
2. **门**：任务门、宿主门、文献只读。
3. **执行**：正在做及其工具、子智能体、命中回执。
4. **证据**：本地查询、外部命中、来源核对、归档/复用、本轮读过、主张绑定。
5. **沉淀**：知识沉淀、Wiki 提案、Zotero 回执。
6. **回答**：本轮引用、回答校验、可回答。

入口、节点选择和正在做是主干位置。工具调用、子智能体和命中是正在做的回执内容，不单独创建执行泳道大卡。没有任何回执的泳道必须显示文档规定的灰色占位文案。

## 事件模型

过程事件按 transcript 的可见顺序归约。每个事件携带稳定的 `seq` 或来源消息序号，避免实时更新覆盖先后关系。

```ts
type ProcessEvent =
  | { type: "user-input"; seq: number; text: string }
  | { type: "turn-route"; seq: number; route: TurnRoute }
  | { type: "tool-receipt"; seq: number; name: string; phase: "start" | "done" | "error"; blockedReason?: string; output?: string }
  | { type: "task-view"; seq: number; view: TaskView }
  | { type: "research-stage"; seq: number; stage: string; details?: Record<string, unknown> }
  | { type: "answer-check"; seq: number; ok: boolean; citations?: string[]; reason?: string };
```

事件提取规则如下：

- 用户消息产生 `user-input`；只有该轮确实重新分类时才产生新的 `turn-route`。`capability_load` 不能改写已经写入的节点选择卡。
- `drone-turn-route` 的公开 `TurnRoute` 是节点选择的唯一来源。`landing` 只允许 `workflow`、`host-gate`、`library`、`ordinary` 四值。
- 工具开始、结束和拒绝产生工具回执；拒绝原因进入正在做三行和任务门/宿主门状态，但不会被当作成功执行。
- `drone-task-status` 的 `TaskView` 负责任务门、宿主门、批准状态、原因码、预算和待审状态。它只投影宿主已经记录的状态。
- `research_loop` 和其他 `research_*` 的公开结果只在实际回执到达时产生研究阶段事件。命中不等于已读，归档不自动进入 `state.reads`。
- `research_check_answer` 的公开结果产生回答校验事件；引用只接受本轮实际读取、哈希一致且未超过 12 条的路径。

归约器输出 `ProcessLaneState`，至少包含：六条泳道及其空文案、节点数组、边数组、当前节点、当前轮次、节点内回执和可展开的明细引用。卡片折行、高度和列数由 renderer 与草图各自的布局层计算，不能混入领域状态。状态对象不包含私有思维文本，也不承担任务或研究账本写入。

## 节点与门的状态规则

节点都有稳定 id、泳道、标题、三行文案、技术码和状态。主干节点使用 `idle`、`active`、`updated`；门节点还使用 `waiting`、`open`、`blocked`；空泳道不创建节点，只渲染灰色占位。

- **用户输入**：每条用户消息最多三行，保留原句的可读摘要。
- **节点选择**：显示阶段、主技能和落点。后来的能力加载不覆盖这张卡。
- **正在做**：每次事件到达都重写三行；工具、子智能体和命中回执嵌在卡内，并可展开公开明细。
- **任务门**：写盘或命令在没有任务契约时为 `waiting`，第三行是 `task-authorization-required`。批准事件只把同一张卡改为 `open`，保留“你点了这一次头”的回执和 `planApproved` 语义。
- **宿主门**：任务进入 `blocked`，或预算、审阅、绑定、未知副作用、幂等回执等宿主原因出现时为 `blocked`。第三行始终保留原因码，例如 `reconcile-before-retry`；不同原因不拆成多张门卡。
- **文献只读**：`landing=library` 时显示只读复用已有文献，并不建立执行边。
- **知识沉淀**：只由真实 deposit 回执请求。`type=source` 与 `type=claim` 保留在第三行或明细中；沉淀不增加本轮引用。
- **本轮引用**：只由当前轮 `reads` 与哈希校验通过的路径请求；显示 `[[路径]]` 条数和上限。`scientificallyVerified` 仍为 `false`。

沉淀和本轮引用之间不建立边。回答校验只能从本轮引用进入，不能从知识沉淀直接连入回答。

## 八步演示的确定语义

草图夹具和正式客户端的回归样例固定为以下八步：

| 步 | 事件与位置变化 | 三行文案重点 | 规则标记 |
| --- | --- | --- | --- |
| 1 | 用户输入 + 节点选择：文献发现 / `nature-academic-search` / 工作流 | 技能写入系统提示；本轮还没执行；命中不算读过 | 否 |
| 2 | 新话题重新选择知识库工作流，上一轮位置卡清掉 | 工作流换成 `research-vault`；阅读和绑定等回执；沉淀不进引用门 | 否 |
| 3 | 新话题重新选择已有计数的差异表达 / `pydeseq2` | 先核对计数和设计；重复要齐；写盘要任务门 | 否 |
| 4 | `read` 成功，更新执行回执 | 改为调用 `read`；只读与 `research_*` 放行；写盘要契约 | 否 |
| 5 | `write` 被任务契约拦截，执行岔到任务门 | 等待确认；写盘先停住；`research_*` 仍放行 | 否 |
| 6 | 批准事件只更新任务门 | 按契约写盘；任务门这一次开过；哈希仍要核对 | **规则演示：仅授权，不代表写盘成功** |
| 7 | 产物哈希变化，执行岔到宿主门 | 停在宿主门；`reconcile-before-retry`；这句不重试 | 否 |
| 8 | `进度如何` 只更新入口和正在做 | 节点选择仍是 `pydeseq2`；宿主门保持关上；这句不重试 | 否 |

第 6 步不得请求宿主门，也不得显示哈希已通过。第 7 步才创建宿主门，并保留任务门。第 8 步不得从宿主门连回正在做；状态提问只是读取并投影既有检查点。

## 边与布局

边只表示公开回执的先后或明确岔路：主干使用实线，进入任务门、宿主门或文献只读使用虚线，状态查询不创建新边，沉淀与引用没有边。边的端点由节点 id 定位，不能依赖当前 DOM 顺序。

过程视图支持 744 与 372 两种栏宽。744 时卡片默认三列，372 时默认两列；卡片高度必须把三行折行、技术码和门卡动作区算入泳道高度。布局完成后应检查：节点之间无重叠、SVG 边不穿越相邻卡片、窄栏不产生横向溢出、门卡按钮不压住下一行。

节点状态、按钮文本和原因码必须同时具备可访问名称。草图门卡动作只跳到对应的演示事件；正式客户端的门卡动作只打开任务面板或定位到已有 `task_reconcile` 回执，不直接授予权限、重跑命令或自动批准 Wiki。

## 正式客户端改动边界

1. 在 `packages/shared/src/process-lanes.ts` 增加类型、事件提取和纯归约器，并从 `packages/shared/src/index.ts` 导出。
2. 在 `packages/desktop/src/renderer/src/components/panel/ProcessPane.tsx` 用六泳道视图替换倒序过程卡片主布局；节点内展开继续使用现有 `RunInspector` 的公开字段。
3. 需要新增的过程视图文案同时写入 `packages/desktop/src/renderer/src/i18n/zh.ts` 与 `en.ts`。不改变任务、研究、知识库或引用规则的授权和持久化实现。
4. 旧 transcript 没有路由、任务或研究回执时，归约器只显示可证明的位置和灰色空泳道；不得用当前模型技能或 Markdown 链接补造执行、已读或回答证据。
5. `/Users/gaoyangwei/test.html` 使用同构字段的八步夹具，展示正式客户端相同的门状态、规则演示标记和布局测量。
6. `outputs/route-lane-sketch.md` 补充代码回执到位置的映射、两拍规则和验收条件；`outputs/drone-base-data.md` 只在代码清单确实新增或移动时更新对应索引，不复制过程状态。

## 验证策略

共享归约器单测覆盖：三次新话题清空与重选、`继续。后面还有正文` 仍为新话题、状态提问保留 `pydeseq2`、任务门批准不等于成功、哈希变化创建宿主门、状态提问不造边、沉淀与引用无边、命中不进入 reads、哈希变化使引用失效，以及旧会话缺少回执时的灰色占位。

草图回归覆盖 0–7 步、744/372 两种宽度和播放/手动跳步；每个快照检查节点重叠、横向溢出、当前节点、门状态、空泳道文案、八步三行文案和边集合。第 6 步必须没有宿主门，第 7 步必须有 `reconcile-before-retry`，第 8 步必须没有宿主门到正在做的边。

正式客户端验证运行与共享包、桌面 renderer 相关的 lint、typecheck 和单测；若索引或导出职责发生变化，更新 `docs/INDEX.md`。不引入新的持久化格式，不修改 `sources/`、Vault 正文、会话正文或 `results/`。

## 风险与取舍

事件提取依赖既有 transcript 的公开字段，旧会话可能只能渲染部分位置；这是可审计的降级，比猜测完整路径安全。把泳道直接替换过程卡片会降低一次浏览中看到的工具明细密度，因此节点内展开必须保留来源、模型、诊断和错误信息。独立 HTML 不能直接 import TypeScript 运行时，所以共享约束通过同构夹具字段和八步快照测试维持；若未来需要避免夹具漂移，再增加构建时导出的 JSON fixture，而不是在浏览器端复制领域逻辑。
