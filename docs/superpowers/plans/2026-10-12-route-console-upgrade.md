# 路由控制台升级方案

## 目标

把“本轮路由”从一条技术泳道升级成可判断、可追踪、可复核的用户入口：用户先看到这轮请求去了哪里、是否需要处理、已经判断了多少步骤，再按需展开全文或导图。

## 本轮落地

- 过程面板增加“本轮路由”摘要，显示原始请求、整体状态和步骤进度。
- 状态优先级固定为：阻塞 → 执行中 → 需要注意 → 可继续，避免节点颜色各说各话。
- 泳道补充列表语义、当前步骤语义、键盘焦点和更明确的导图/解释按钮标签。
- 过程面板保留默认紧凑视图；详细回执仍在泳道节点中按需展开，不增加聊天噪音。

## 下一阶段

1. 在右侧“过程”面板加入按轮次筛选的路由摘要，与泳道节点联动定位。
2. 对阻塞节点提供就地动作入口：查看任务契约、宿主复核、重放 evidence capsule。
3. 将 P0–P4 的 contract、provenance、adapter、proposal、capsule 状态映射到同一套状态徽标，并为每个状态提供可复制的审计摘要。
4. 增加真实 Electron IPC 的端到端回放测试，覆盖“用户输入 → route custom message → UI 卡片 → 决策/证据动作”的完整链路。

## 验收标准

- 新话题、接续、问进度和宿主门在路由卡上有不同的状态和解释。
- 任何 P0–P4 关键路径都有可运行测试，并且至少有一项跨层测试验证真实产物或持久化结果。
- 低宽度窗口下路由步骤可以横向滚动，按钮可键盘聚焦，减少动画设置下不依赖动画表达状态。
